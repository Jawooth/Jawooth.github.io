# 改站指南（零基础版）

> **这份文档写给完全不会写代码的你。**
> 你不需要懂 HTML、CSS、JavaScript，也不需要记住任何命令。
> 只要会「打开软件 → 改文字 → 点一个按钮」，就能维护这个博客。
>
> 遇到看不懂的地方，直接跳到 **第 10 节「出问题了怎么办」**。

---

## 0. 心里先有这三件事

| # | 事情 | 怎么做 |
|---|---|---|
| 1 | **想立刻看效果** | 打开 **HexoHub** → 点左边「本地预览」（或【启动服务器】），浏览器开 **http://localhost:4000/** |
| 2 | **想让别人看到（上线）** | 关掉 HexoHub 的预览 → 双击文件夹里的 **`发布.cmd`** → 等它自己跑完 |
| 3 | **改坏了想变回原样** | 命令行（或让 AI 帮你）跑 `git checkout -- .`；**动手前**双击 `备份.cmd` 更保险 |

**最重要的一条习惯**：**每次动文章或图片之前，先双击 `备份.cmd`。** 它会把文章、图片、数据都复制一份到 `backup\` 文件夹，改坏了随时能翻回来。

## 1. 一张表：我想改什么，该动哪里

### 1.1 在 HexoHub 软件里点几下就能改的

HexoHub 是这个博客的「操作面板」，管的是**文章 + 图片 + 建成上传**这三件事
（官方功能说明：<https://github.com/forever218/HexoHub>）。

| 我想… | 在 HexoHub 里怎么点 |
|---|---|
| 写一篇新文章 | 点 **+**（或【创建新文章】）→ 填「文章标题」→ 写正文 |
| 改一篇已有文章 | 左边文章列表里点它 → 直接改（Ctrl+S 保存）→ 切到「预览」看效果 |
| 文章里插一张图 | 把图片文件**直接拖进编辑框**（会自动放好图片并填上引用） |
| 按标签/分类找文章 | 文章列表上方的「按标签 / 按分类」筛选，或用左侧标签云 |
| 一次给多篇文章加标签 / 删多篇 | 列表里勾选（全选）→【添加标签】【添加分类】【删除】 |
| 调整列表排序、搜索文章 | 按文件名 / 修改时间 / 发布日期排序；搜索框输入标题 |
| 改网站名字、描述、作者 | 【配置】→ 基本设置（写进 `_config.yml`） |
| 改网址、永久链接格式 | 【配置】→ 高级设置 |
| 生成网页文件 | 【清理】+【生成】（等于 `hexo clean` + `hexo generate`） |
| 一键发布上线 | 【部署】（等于 `hexo deploy`） |
| 直接改 `_config.yml` 原文 | 【配置】里的「原始配置」文本框（YAML） |
| 用别的编辑器打开当前文章 | 编辑器工具栏的【外部编辑器】 |
| 看命令执行成功还是失败 | 【查看日志】（会显示 ✓ 成功 / ✗ 失败与错误详情） |
| 让 AI 帮忙改写文章 | 选中文字 → 右键 → AI 工具（需先在面板里配 API Key） |

**HexoHub 能碰到哪些文件（很重要）**：

- ✅ 文章：`source\_posts\` 下的 `.md`（新建、编辑、批量改标签/分类、删除）
- ✅ 图片：拖进编辑器后复制到 `source\_posts\<文章名>\`，插成 `{% asset_img 文件名 "描述" %}`
- ✅ 站点主配置：`_config.yml`（基本设置 / 高级设置 / 原始配置 YAML）
- ✅ 生成结果：`public\`（生成成功后有【打开】链接）
- ❌ **不碰** `source\_data\*.yml`（网名、句子、待办、清单、歌单都在这里）
- ❌ **不碰** `_config.minimalism.yml`（导航菜单、页脚图标）
- ❌ **不碰** `source\css\`、`themes\`、`scripts\`（样式、模板、脚本）

> 后三项 HexoHub 没有界面，**只能用记事本或代码编辑器改**，见下面的 1.2。
>
> **说明**：本节按 HexoHub 官方文档与它的界面源码整理（[项目地址](https://github.com/forever218/HexoHub)），**没有逐一点击实测**。
> 软件更新后按钮叫法可能变；**以你看到的软件为准**，不一样就回来改掉这段。

### 1.2 要用记事本改的（HexoHub 管不到）

这些是「数据文件」，格式简单、有中文注释，**用记事本改字就行，不要改冒号和缩进**。

| 我想改… | 用记事本打开这个文件 |
|---|---|
| **网名、头像、自我介绍、社交图标链接、多个邮箱** | `source\_data\profile.yml` |
| **首页便签上轮换的句子** | `source\_data\quotes.yml` |
| **待办清单**（显示在杂谈页） | `source\_data\todo.yml` |
| **游戏/工具卡片**（游戏页） | `source\_data\apps.yml` |
| **攻略/教程清单**（攻略页） | `source\_data\guides.yml` |
| **首页播放器的歌单、窗口标题** | `source\_data\music.yml`（换歌单后要跑 `py -3 tools\fetch-netease.py`） |
| 头像 / 壁纸 / 作品图 | 直接**覆盖** `source\images\` 里的同名图片（见第 5 节） |
| 导航菜单、页脚图标、RSS | `_config.minimalism.yml`（**进阶**，改前先备份） |

> **怎么用记事本打开？** 在文件上**右键 → 打开方式 → 记事本**。
> 存盘时选「文件 → 保存」即可，**不要**另存为 `.txt`，否则网站读不到。
>
> ⚠️ **别用 PowerShell 命令去批量改中文文件**（会把中文变成 `?`，直接改坏）。

### 1.3 不属于上面两类的

改页面版式、颜色、模板这些属于「改代码」，看 **[手册：MAINTENANCE.md](MAINTENANCE.md)**，或者直接交给 AI 助手做。

## 2. 在 HexoHub 里干活的完整流程

### 2.1 打开项目

1. 双击 **`D:\tools\HexoHub\hexohub.exe`**
2. 让它打开博客目录 **`D:\tools\hexo`**（第一次需要选一次，以后它会记住）
3. 能看到文章列表，就说明打开对了

### 2.2 写一篇新文章

1. 点列表上方的 **+** /【创建新文章】，弹出「创建新文章」窗口
2. 填进去：
   - **文章标题**（必填，可以写中文，例如 `我的第一张板绘`）
   - **标签**：输入后按回车添加（可以点下拉里已有的标签）
   - **分类**：输入后按回车添加
   - **摘要**：可选的「一句话简介」，会显示在卡片上（等于 front matter 的 `desc`）
3. 写正文。正文就是普通文字，工具栏上有现成按钮：
   - 【标题 1 / 标题 2 / 标题 3】= 小标题，【粗体】【斜体】【引用】【表格】【代码块】…
4. **写完按 `Ctrl + S` 保存**，再点【生成】，然后到预览里刷新看看

> **文章最上面那几行**（`---` 之间的部分）叫 front matter，是文章的属性设置。
> HexoHub **只为标题/标签/分类/摘要提供输入框**，其它字段（`origin`、`thumbnail`、`status`…）
> 要**自己在那段 `---` 里加一行**，见第 4 节。
>
> 💡 小技巧：HexoHub 新建文章时会读 `scaffolds\post.md`（本仓库已放好带说明的模板），
> 所以新建的文章里会自带一段中文注释提示。

### 2.3 往文章里插图片

1. 把图片文件**直接拖进编辑框** → 软件会把图片复制到 `source\_posts\<文章文件名>\` 下，并插入 `{% asset_img 图片名 "描述" %}`
2. 打开文章所在的文件夹时，图片会和文章一起发布

> **两件要注意的事**：
> 1. 这样插的图只是「正文里的图」。**卡片封面只认 front matter**：想让这张画出现在
>    **首页「最近作品」或作品页的卡片封面**上，还得按第 5 节另外放一张图、并在 front matter 里写 `thumbnail:`。
> 2. 本仓库的 `_config.yml` **已经打开了 `post_asset_folder`**（这是拖图功能的前提）。
>    万一以后有人把它改回 `false`，HexoHub 会弹窗问你要不要自动开启——选「是」即可，它会帮你改 `_config.yml`。

### 2.4 看效果

| 你想看 | 怎么做 |
|---|---|
| 在 HexoHub 里看 | 编辑器切到「预览」标签；或【启动服务器】后浏览器开 **http://localhost:4000/** |
| 用命令行预览 | 双击 **`预览.cmd`**，浏览器开 **http://127.0.0.1:4010/** |

> **两个预览不要同时开**（会抢 4000 端口）。
> **别**直接双击 `public\index.html` 打开——那样图片和样式都会丢失，看起来像网站坏了。
>
> 预览打不开、或提示端口被占用时，HexoHub 有【停止服务器】和「立即修复」（会结束占用 4000 端口的进程）可用。

### 2.5 发布上线

**两条路，选一条就行**：

- **① 用 HexoHub**：【清理】→【生成】→【部署】（可以在【查看日志】里确认 ✓ 成功）
- **② 用双击脚本**（更稳，脚本会检查每一步的成败）：
  1. **先关掉 HexoHub 的预览服务器**
  2. 双击 **`发布.cmd`**，等它跑完（它会自动 清理 → 生成 → 上传）
  3. 打开 <https://jawooth.github.io/> 按 **Ctrl + F5** 强制刷新

> 上传后 GitHub 还要自己跑半分钟到两分钟，网页才会更新，**这是正常的**。
> 如果卡在 `Writing objects: 100%` 不动，看 [MAINTENANCE.md 第 12 节](MAINTENANCE.md)。

> ⚠️ **在 HexoHub 里删文章之前，先双击 `备份.cmd`。**
> 客户端的删除是直接删文件、不进回收站（会问一次「此操作不可撤销」），而且站点靠 Git 记录历史，删掉后要么从 `backup\` 找回来，要么用 `git checkout -- .` 撤回。

### 2.6 软件里几个「顺手」的设置

都在【面板设置】里（每个选项旁边都有说明，看不懂就别动）：

| 设置 | 作用 |
|---|---|
| 每页显示文章数量 | 文章列表一页显示多少篇（默认 15） |
| 自动保存间隔（分钟） | 编辑时每隔几分钟自动存一次 |
| 背景图片 / 背景透明度 | 只改软件的外观，**不影响网站** |
| 编辑模式 | 模式 1 = 编辑/预览切换；模式 2 = 左右分栏 |
| 预览模式 | 「静态预览」或「服务器预览」（后者用 4000 端口的真服务器） |
| 界面语言 / 明亮·黑夜模式 | 只改软件自己的界面 |
| 启用 AI（可选） | 用自己的 API Key（DeepSeek / OpenAI / 硅基流动）启用右键的 AI 改写功能。**不配也不影响其它功能** |

【关于】里能看到版本号并【检查更新】。

## 3. 日常「我改完了，接下来做什么」

| 你改了什么 | 要做什么 |
|---|---|
| 文章（`source\_posts\`） | HexoHub 里【清理】+【生成】，或双击 `构建.cmd` |
| `source\_data\` 里的文件（名字、句子、待办、清单…） | **必须重新生成**，而且要**重启预览服务器**才会看到新内容 |
| 图片（头像、壁纸、作品图） | 同文章：重新生成 |
| 想上线 | 关预览 → 双击 `发布.cmd` |

**为什么 `_data` 要重启预览？** 因为预览服务器只在启动时读一次这些数据文件，改了它不会自动知道。**这不是你改错了。**

## 4. 文章最上面那段（front matter）怎么填

普通文章这样写就够了：

```yaml
---
title: 我的第一张板绘        # 标题（HexoHub 新建文章时会自动填）
date: 2026-10-11 20:00:00   # 日期，决定排序和网址
tags: [板绘, 练习]           # 标签，会出现在标签云和标签页
---
```

如果这是一件**作品**（要出现在作品页），再加上这几行：

```yaml
---
title: 风景插画·山间小屋
date: 2026-09-28 14:30:00
categories: [作品, 插画]     # 第一个必须是「作品」，后面的会变成分类标签
origin: 原创                # 原创 或 同人（决定进作品页哪个栏目）
tags: [风景, 数码绘画]
short_title: 山间小屋        # 卡片上显示的短标题（不填就用 title）
desc: 一句话简介，会显示在卡片和最近作品里
img: /images/works/landscape.jpg            # 文章顶部大图
thumbnail: /images/works/landscape-thumb.jpg # 卡片封面（用 -thumb 小图，省流量）
status: done                # done = 已完成，doing = 进行中（卡片角标）
---
```

**三条容易踩的规则**：

1. **作品必须写 `categories: [作品, …]`** —— 少了「作品」这两个字，这篇文章就从作品页和首页消失了（**不报错**，只是没了）。
2. **`origin` 只能填 `原创` 或 `同人`**，不填就按原创算。
3. **文件名决定网址**：请用**英文和短横线**，例如 `work-my-first-painting.md`。
   用中文文件名，网址会变成 `%E4%BD%9C...` 这种看不懂的编码。

> **作品的时间轴分期不用你管**：系统按 `date` 自动归入。真想手动指定，才加一行 `era: 2025 年`。
>
> **首页「最近作品」里的卡片必须有 `thumbnail:`**，否则那张卡不会出现。

更细的字段说明（每个字段能填什么、不填会怎样、改错什么现象）见 **[CONTENT-GUIDE.md](CONTENT-GUIDE.md)**。

## 5. 图片怎么换（记住「覆盖同名文件」这一招）

**最简单的办法**：找一张新图，改成下面这个文件名，然后**覆盖**原来的图片文件。改完重新生成即可。

| 想换什么 | 覆盖这个文件 | 建议 |
|---|---|---|
| 头像 | `source\images\site-avatar.png` | 正方形，256×256 |
| 浅色壁纸 | `source\images\xp-desktop-bg.jpg` | 1920×1080 以内 |
| 深色壁纸 | `source\images\xp-desktop-bg-dark.jpg` | 同上 |
| 浏览器标签页图标 | `source\favicon.ico` | 图标文件 |
| 首页两侧装饰图 | `source\images\decor\left.png`、`right.png` | 窗口宽度 ≥1500px 时才显示 |

**作品图建议用现成的导入工具**（会自动生成大图和缩略图，并把原图备份到 `backup\`）：

```powershell
cd D:\tools\hexo
py -3 tools\add-artwork.py "D:\我的画\山间小屋.png" landscape-cottage --title "风景插画·山间小屋" --desc "一句话简介"
```

它会打印一段填好的 front matter，**复制粘贴到文章最上面**就行。

> **为什么用 `py -3` 而不是 `python`？** 这台电脑的 `python` 是 Windows 商店的占位程序，直接敲会提示「Python was not found」。用 `py -3` 才会真正运行已安装的 Python 3.13（本机已装好 Pillow，图片工具可以直接用）。
> 若提示缺 Pillow：`py -3 -m pip install Pillow`。

> ⚠️ **头像文件名不要改叫 `avatar.png`** —— 那是主题自带的占位图，会把你的覆盖掉。

## 9. 想彻底换成自己的内容？照着这个清单过一遍

现在站上的示例内容分两类，**过一遍就知道哪些是你自己的、哪些还是样例**：

| 位置 | 现在的状态 | 你要做的 |
|---|---|---|
| `_config.yml` 的 `title` / `description` / `author` | 还是「我的小站」「Jawooth」这类占位 | 换成你的站名（HexoHub 配置页也能改） |
| `source\_data\profile.yml` | 已是站主自己的网名/邮箱/链接 | 核对一遍即可 |
| `source\_data\quotes.yml` | 已是站主自己的句子 | 想加就加（一句别超 60 字） |
| `source\_data\todo.yml` | 站主的待办 | 改成你现在的计划 |
| `source\_data\apps.yml` | 「打砖块/贪吃蛇/计算器」等**尚未上线**的规划 | 有成品就把 `status` 改 `online` 并补 `url`；没做就先留着 |
| `source\_data\guides.yml` | 8 条**还没写**的攻略/教程计划 | 写完文章后把该条 `status` 改成 `online`、补上 `url` |
| `source\_posts\hello-world.md` | Hexo 自带示例 | 可以留着当格式参考，也可以删 |
| `source\_posts\work-*.md` | 3 篇作品示例 | 换成你的作品（用第 5 节的导入工具）或删掉 |
| `source\images\` 里的图 | 示例图 | 按第 5 节覆盖成你自己的 |

**替换完统一做三件事**：

```
1. 双击 构建.cmd          （重新生成）
2. py -3 tools\verify-site.py      （自检：有没有断链、有没有没渲染的东西）
3. 关掉预览 → 双击 发布.cmd          （上线）
```

## 10. 出问题了怎么办

| 现象 | 多半是这个原因 | 怎么办 |
|---|---|---|
| 改了 `_data` 里的文件，预览没变化 | 预览服务器只在启动时读一次数据文件 | **重启预览服务器**，再重新生成 |
| 改了东西，网站没变 | 忘了重新生成 | 双击 `构建.cmd`（或 HexoHub 里【清理】+【生成】） |
| 样式改了没反应 | 浏览器缓存 | 按 **Ctrl + F5** 强制刷新 |
| 双击 `public\index.html` 打开，页面是纯文字、图全没了 | 这是构建产物，不能用 `file://` 直接打开 | 老老实实用 4000 或 4010 端口预览 |
| 中文变成 `?` 或 `??` | 用 PowerShell 命令改过中文文件 | 用 `git checkout -- .` 撤回，改用记事本改 |
| 页面里冒出一堆 `{% xp_xxx %}` 原文 | 模板标签没被渲染（多半是缩进/注释踩坑） | 跑 `py -3 tools\verify-site.py` 看是哪一页，再对照 MAINTENANCE 第 8 节 |
| 发布卡在 `Writing objects: 100%` | 代理 + HTTP/2 的老毛病 | 见 [MAINTENANCE.md 第 12 节](MAINTENANCE.md) |
| 网站整个打不开了 | 先别慌，看是不是改坏了 | 双击 `备份.cmd` 留底 → `git checkout -- .` 撤回 → 重新生成 |
| 完全不知道从哪下手 | — | 把 [MAINTENANCE.md](MAINTENANCE.md) 发给 AI 助手，说「我要改 XX」 |

**万能兜底**：任何一步「好像坏了」，先 `git checkout -- .` 撤回，网站就回到上次能用的样子，然后慢慢再来。

## 11. 常用的四个双击按钮

| 文件 | 干什么 | 什么时候用 |
|---|---|---|
| `构建.cmd` | 重新生成网站（清理 + 生成） | 改完文章/图片/数据之后 |
