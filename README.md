# 改站指南（零基础版）

> **这份文档写给完全不会写代码的你。**
> 你不需要懂 HTML、CSS、JavaScript，也不用记任何命令。
> 会「双击一个文件 → 按一个数字 → 改几个字」就够了。
>
> 哪一步看不懂，直接跳到 **[第 8 节「出问题了怎么办」](#8-出问题了怎么办)**。

## 0. 只记一件事：双击 `1 开始使用.cmd`

博客文件夹 `D:\tools\hexo` 里，**你只需要认一个文件**：

```
1 开始使用.cmd        ← 双击它，下面所有事都能做
```

双击后会出来一个**中文菜单**，按数字选就行：

| 按 | 做什么 | 什么时候用 |
|---|---|---|
| **1** | 写 / 改文章 | 打开 HexoHub 编辑器：写文章、拖图片进去 |
| **2** | **看效果** | **改完东西必点**：重新生成 + 自动打开浏览器预览 |
| **3** | 发布上线 | 满意了，上传到线上，别人就能看到了 |
| **4** | 先备份 | 动手**删东西 / 换图片之前**，先留个底 |
| **5** | **撤回改动** | 改坏了？一步回到上次能用的样子（后悔药） |
| **6** | 更新歌单 | 换了网易云歌单之后（很少用） |
| **7** | 全面自检 | 检查有没有断链、没渲染出来的标签、图片是不是太大 |
| **0** | 退出 | 干完活关掉它 |

**日常只要记两个数字：改东西用 `1`，看效果用 `2`。满意了再按 `3`。**

每做完一件事它会**回到菜单**，你可以接着选下一件；不想继续就按 `0`。

### 0.1 三个最容易搞混的问题，这里一次说清

**问题一：改东西，用 HexoHub 还是用这个脚本？**

> **改内容用 `1`（HexoHub）；改完要「生效」用 `2`。** 两者不冲突：

| 你想干的事 | 用哪里 | 为什么 |
|---|---|---|
| 写文章、改文章、插图片、批量改标签、删文章 | **`1`（HexoHub）** | 只有它有编辑器 |
| 改网名、自我介绍、首页句子、待办、游戏/攻略清单、歌单 | **记事本**（HexoHub 管不到这些） | 这些是 `source\_data\` 下的数据文件 |
| 让改动「生效」 | **`2`** | Hexo 不会自动感应，必须重新生成 |
| 生成 + 上传一条龙 | **`3`** | 它就是 清理 → 生成 → 上传 |

> HexoHub 里那些【清理】【生成】【部署】按钮，和菜单 `2`、`3` 干的是同一件事。
> **建议用菜单**：它会检查预览有没有开着、每一步成没成功，出错时告诉你失败在哪一步；
> HexoHub 的按钮不会。

**问题二：本地预览在哪儿？**

> **别记端口号，按 `2` 就行。** 它会自己判断：已经开着预览就直接打开，没开就帮你开一个。
> 两个地址分别是：
>
> - `http://localhost:4000/` —— 你在 **HexoHub 里**点【启动服务器】时用的
> - `http://127.0.0.1:4010/` —— **菜单 `2`** 自己起的预览
>
> **两个预览不要同时开**（会互相抢端口、打断构建）。菜单 `2` 起的预览窗口**不要关**，
> 关掉就等于关掉预览。

**问题三：按了发布，线上却没变？**

> 按顺序查这三条，基本一步就能定位：
>
> 1. **发布窗口最后一行是不是 `✓ 完成`？** 不是的话，看它指出的失败步骤。
>    最常见的两种：
>    - **提示 4000 端口被占用**：那是 HexoHub 的预览开着，会打断构建。**按提示停掉它。**
>    - **`TLS connect error` / `unable to access`**：本机代理（Clash Verge）掉了。
>      **内容没丢**，重新按 `3`，选 **[1] 只重传** 即可。
> 2. **GitHub 还要 30–120 秒**才发布完，用 `Ctrl + F5` 强制刷新。
> 3. 想确认到底传上去没有：按 `7` 自检，或看菜单 `3` 最后打印的提示。

### 0.2 完整一圈长这样

```
  ① 菜单按 1  写点东西            （或用记事本改 source\_data 里的文件）
                 ↓
  ② 菜单按 2  看效果              ← 不满意就回到 ①
                 ↓
  ③ 菜单按 3  发布上线
                 ↓
  ④ 打开 https://Jawooth.github.io/  按 Ctrl+F5
```

**唯一要养成的习惯：动文章或图片之前，先按 `4` 备份一次。**
它会把文章、图片、数据复制到 `backup\` 文件夹，改坏了随时能翻回来。

## 1. 我想改什么，该动哪里

### 1.1 在 HexoHub 里点几下就能改的（菜单 `1`）

HexoHub 是这个博客的「操作面板」，管**文章 + 图片 + 生成上传**这三件事
（官方说明：<https://github.com/forever218/HexoHub>，已装在 `D:\tools\HexoHub\hexohub.exe`，
仓库外面，不会被发布出去）。

| 我想… | 在 HexoHub 里怎么点 |
|---|---|
| 写一篇新文章 | 点 **+**（或【创建新文章】）→ 填标题 → 写正文 |
| 改一篇已有文章 | 左边列表里点它 → 直接改（`Ctrl + S` 保存）→ 切到「预览」看效果 |
| 文章里插一张图 | 把图片文件**直接拖进编辑框**（会自动放好图片并填上引用） |
| 按标签/分类找文章 | 列表上方的「按标签 / 按分类」筛选，或用左侧标签云 |
| 一次给多篇加标签 / 删多篇 | 列表里勾选（可全选）→【添加标签】【添加分类】【删除】 |
| 改网站名字、描述、作者 | 【配置】→ 基本设置（写进 `_config.yml`） |
| 看命令成功还是失败 | 【查看日志】（✓ 成功 / ✗ 失败与错误详情） |
| 让 AI 帮忙改写文章 | 选中文字 → 右键 → AI 工具（需先配 API Key） |

**HexoHub 能碰到哪些文件（很重要）**：

- ✅ 文章：`source\_posts\` 下的 `.md`（新建、编辑、批量改标签、删除）
- ✅ 图片：拖进编辑器后复制到 `source\_posts\<文章名>\`，插成 `{% asset_img 文件名 "描述" %}`
- ✅ 站点主配置：`_config.yml`
- ❌ **不碰** `source\_data\*.yml`（网名、句子、待办、清单、歌单都在这里）
- ❌ **不碰** `_config.minimalism.yml`（导航菜单、页脚图标）
- ❌ **不碰** `source\css\`、`scripts\`、`themes\`（样式、脚本、模板）

> 后三项 HexoHub 没有界面，只能用记事本改，见下面 1.2。

### 1.2 要用记事本改的（HexoHub 管不到）

这些是「数据文件」，格式简单、每行都有中文注释，**只改冒号后面或引号里的字，
不要改冒号和缩进**。

| 我想改… | 用记事本打开这个文件 |
|---|---|
| **网名、头像、自我介绍、社交图标链接、多个邮箱** | `source\_data\profile.yml` |
| **首页便签上轮换的句子** | `source\_data\quotes.yml`（两侧的「」也能在这里换掉或去掉） |
| **待办清单**（显示在杂谈页） | `source\_data\todo.yml` |
| **游戏/工具卡片**（游戏页） | `source\_data\apps.yml` |
| **攻略/教程清单**（攻略页） | `source\_data\guides.yml` |
| **作品页的分期与栏目** | `source\_data\works.yml` |
| **播放器的曲目、窗口标题** | `source\_data\music.yml`（换网易云歌单后按 `6`） |
| 头像 / 壁纸 / 作品图 | 直接**覆盖** `source\images\` 里的同名图片（见第 5 节） |
| 导航菜单、页脚图标 | `_config.minimalism.yml`（**进阶**，改前先按 `4` 备份） |

> **怎么用记事本打开？** 在文件上**右键 → 打开方式 → 记事本**。
> 存盘选「文件 → 保存」即可，**不要**另存为 `.txt`，否则网站读不到。
>
> ⚠️ **别用 PowerShell 命令去批量改中文文件**（可能把中文变成 `?`）。
> 改中文文件就用记事本，或者让 AI 助手改。

### 1.3 剩下的（改版式、颜色、模板）

那属于「改代码」，看 **[手册.md](手册.md)**，或者直接交给 AI 助手。

### 1.4 文件夹地图（记不住没关系，用到再回来看）

```
D:\tools\hexo
```

## 2. 在 HexoHub 里写一篇文章

1. 菜单按 `1` 打开 HexoHub（第一次要让它打开博客目录 `D:\tools\hexo`，之后会记住）
2. 点 **+** /【创建新文章】，填：
   - **文章标题**（必填，可以是中文）
   - **标签**：输入后回车；**分类**：输入后回车
   - **摘要**：可选的「一句话简介」，会显示在卡片上
3. 写正文。工具栏有现成按钮：【标题 1/2/3】【粗体】【引用】【表格】【代码块】…
4. **写完按 `Ctrl + S` 保存**，然后回到菜单按 `2` 看效果

> 文章最上面 `---` 之间的那几行叫 **front matter**，是文章的属性设置。
> HexoHub 只给标题/标签/分类/摘要提供输入框，其它字段要自己加一行 —— 见第 4 节。
>
> 想往文章里插图：**把图片拖进编辑框**即可，它会自动复制并填好引用。
>
> ⚠️ 这样插的图只是「正文里的图」。想让这张画出现在**首页「最近作品」或作品页卡片**上，
> 还得按第 5 节另外放一张封面图、并在 front matter 里写 `thumbnail:`。

## 3. 改完「生效」的规则

| 你改了什么 | 要做什么 |
|---|---|
| 文章（`source\_posts\`） | 菜单按 `2` |
| `source\_data\` 里的文件 | 菜单按 `2`（**必须先关掉预览窗口**，见下） |
| 图片（头像、壁纸、作品图） | 菜单按 `2` |
| 只改了 CSS（`source\css\xp-custom.css`） | **不用重新生成**，浏览器 `Ctrl + F5` 刷新即可 |
| 想上线 | 菜单按 `3` |

> **为什么改 `_data` 要先关预览？** 预览服务器在**启动时**就把这些数据读进内存了，
> 之后改文件它不会重读。顺序是：**关掉预览窗口 → 菜单按 `2`**（它会把预览重新起一份）。
> **这不是你改错了。**

## 4. 文章最上面那段（front matter）怎么填

普通文章这样写就够了：

```yaml
---
title: 我的第一张板绘        # 标题
date: 2026-10-11 20:00:00   # 日期，决定排序和网址
tags: [板绘, 练习]           # 标签
---
```

如果这是一件**作品**（要出现在作品页），再加上这几行：

```yaml
---
title: 风景插画·山间小屋
date: 2026-09-28 14:30:00
categories: [作品, 插画]     # 第一个必须是「作品」，后面的会变成分类标签
origin: 原创                # 原创 或 同人（决定进作品页哪个栏目）
tags: [风景, 数码绘画]
short_title: 山间小屋        # 卡片上的短标题（不填就用 title）
desc: 一句话简介，会显示在卡片和最近作品里
img: /images/works/landscape.jpg             # 文章顶部大图
thumbnail: /images/works/landscape-thumb.jpg # 卡片封面（用 -thumb 小图省流量）
status: done                # done = 已完成，doing = 进行中（卡片角标）
---
```

**三条最容易踩的规则**：

1. **作品必须写 `categories: [作品, …]`**。少了「作品」两个字，这篇文章就从作品页和首页
   消失了 —— **不会报错**，只是没了。
2. **`origin` 只能填 `原创` 或 `同人`**（这两个词可以在 `source\_data\works.yml` 里改）。不填算原创。
3. **文件名决定网址**：请用**英文和短横线**，例如 `work-my-first-painting.md`。
   用中文文件名，网址会变成 `%E4%BD%9C...` 这种看不懂的编码。

> **作品的时间轴分期不用你管**：系统按 `date` 自动归入。想手动指定，加一行 `era: 2025 年`。
> 分期本身可以在 `source\_data\works.yml` 里改。
>
> **首页「最近作品」的卡片必须有 `thumbnail:`**，否则那张卡不会出现。

每个字段能填什么、填错会怎样，见 **[手册.md](手册.md)** 的字段表。

## 5. 图片怎么换（记住「覆盖同名文件」这一招）

**最简单的办法**：找一张新图，改成下面这个文件名，然后**覆盖**原来的图片文件，再按 `2`。

| 想换什么 | 覆盖这个文件 | 建议 |
|---|---|---|
| 头像 | `source\images\site-avatar.png` | 正方形，256×256 |
| 浅色壁纸 | `source\images\xp-desktop-bg.jpg` | 1920×1080 以内 |
| 深色壁纸 | `source\images\xp-desktop-bg-dark.jpg` | 同上 |
| 浏览器标签页图标 | `source\favicon.ico` | 图标文件 |

**作品图建议用现成的导入工具**（自动生成大图和缩略图，并把原图备份到 `backup\`）：

```
py -3 tools\add-artwork.py "D:\我的画\山间小屋.png" landscape-cottage --title "风景插画·山间小屋" --desc "一句话简介"
```

它会打印一段填好的 front matter，**复制粘贴到文章最上面**就行。

> **为什么是 `py -3` 而不是 `python`？** 这台电脑的 `python` 是 Windows 商店的占位程序，
> 直接敲会提示「Python was not found」。用 `py -3` 才会真正运行已装的 Python。
> 若提示缺 Pillow：`py -3 -m pip install Pillow`。

> ⚠️ **头像文件名不要改成 `avatar.png`** —— 那是主题自带的占位图，会把它覆盖掉。

> 首页两侧的装饰图是**可选项**：把图放进 `source\images\decor\`，命名成 `left.png` / `right.png`
> 就会显示（只在窗口宽度 ≥1500px 时）；不放就什么都不显示，**不会报错**。

## 6. 后悔药：备份与撤回

| 我想… | 怎么做 |
|---|---|
| 动手前留个底 | 菜单按 `4`（结果在 `backup\` 文件夹里） |
| **放弃刚才所有改动** | 菜单按 `5`（会把没提交的改动全部撤回到上次能用的状态） |
| 看今天改了什么 | 让 AI 助手跑 `git status`，或看菜单 `5` 的提示 |
| 让别人（或 AI）接手改站 | 把 [手册.md](手册.md) 的「给 AI 助手的交接说明」一节发给它 |

> `backup\` 文件夹不进仓库、不会被发布，可以放心堆。
> 按 `5` 撤回**不会**动 `backup\`，所以「先备份，再撤回」是最稳的顺序。

## 7. 想彻底换成自己的内容？照着这个清单过一遍

站上的示例内容分两类，过一遍就知道哪些还是样例：

| 位置 | 现在的状态 | 你要做的 |
|---|---|---|
| `_config.yml` 的 `title` / `description` / `author` | 占位站名 | 换成你的站名（HexoHub 配置页也能改） |
| `source\_data\profile.yml` | 已是站主自己的网名/邮箱/链接 | 核对一遍 |
| `source\_data\quotes.yml` | 已是站主自己的句子 | 想加就加（一句别超 60 字） |
| `source\_data\todo.yml` | 站主的待办 | 改成你现在的计划 |
| `source\_data\apps.yml` | 还没上线的游戏/工具规划 | 有成品就把 `status` 改 `online` 并补 `url` |
| `source\_data\guides.yml` | 还没写的攻略计划 | 写完后把该条 `status` 改 `online`、补 `url` |
| `source\_data\works.yml` | 作品分期与栏目 | 按你的作品年份调整 |
| `source\_posts\hello-world.md` | Hexo 自带示例 | 可留着当格式参考，也可删 |
| `source\_posts\work-*.md` | 3 篇作品示例 | 换成你的（用第 5 节的导入工具）或删掉 |
| `source\images\` 里的图 | 示例图 | 按第 5 节覆盖成你自己的 |

**替换完统一做三件事**：

```
1. 菜单按 2    （改动生效，并在浏览器里看一眼）
2. 菜单按 7    （自检：有没有断链、有没有没渲染的东西）
3. 菜单按 3    （发布上线）
```

## 8. 出问题了怎么办

### 8.1 按现象查

| 现象 | 多半是这个原因 | 怎么办 |
|---|---|---|
| **发布了，线上却没变** | 见 [0.1 问题三](#01-三个最容易搞混的问题这里一次说清) | 先看发布窗口最后一行是不是 `✓ 完成` |
| 提示 4000 端口被占用 | HexoHub 的预览开着，会打断构建 | 按提示停掉它，再继续 |
| 报 `TLS connect error` / `unable to access` | 本机代理（Clash Verge）掉了。**内容没丢** | 重新按 `3`，选 **[1] 只重传** |
| 卡在 `Writing objects: 100%` 不动 | 代理 + HTTP/2 的老毛病 | 再按一次 `3` 选只重传；或看 [手册.md](手册.md) 部署一节 |
| 改了 `_data` 里的文件，预览没变化 | 预览只在启动时读一次数据 | 关掉预览 → 菜单按 `2` |
| 改了东西，网站没变 | 忘了重新生成 | 菜单按 `2` |
| 样式改了没反应 | 浏览器缓存 | `Ctrl + F5` 强制刷新 |
| 双击 `public\index.html` 打开，页面是纯文字、图全没了 | 那是构建产物，不能用 `file://` 直接打开 | 用菜单 `2` 打开预览 |
| 中文变成 `?` 或 `??` | 用 PowerShell 命令改过中文文件 | 菜单按 `5` 撤回，改用记事本改 |
| 页面里冒出一堆 `{% xp_xxx %}` 原文 | 模板标签没被渲染（多半是缩进/注释踩坑） | 按 `7` 自检，看是哪一页；再对照 [手册.md](手册.md) |
| 网站整个打不开了 | 先别慌，八成是改坏了 | 按 `4` 留底 → 按 `5` 撤回 → 按 `2` 看效果 |
| 敲 `py -3 tools\xxx.py` 报「找不到文件」 | 你不在博客目录里 | 双击 `1 开始使用.cmd` 最省事 |
| 完全不知道从哪下手 | — | 把 [手册.md](手册.md) 发给 AI 助手，说「我要改 XX」 |

### 8.2 万能兜底

**任何一步「好像坏了」，先按 `5` 撤回**，网站就回到上次能用的样子，然后慢慢再来。
撤回前想保险，就先按 `4` 备份。
