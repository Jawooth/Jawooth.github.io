## 0. 只记一件事：双击「1 开始使用.cmd」

博客文件夹 `D:\tools\hexo` 里，**你只需要认一个文件**：`1 开始使用.cmd`。
双击后出现中文菜单（引擎是 `tools\hexo-ui.ps1`，平时不用管），按数字选：

| 按 | 做什么 | 什么时候用 |
|---|---|---|
| **1** | 写 / 改文章 | 打开 HexoHub 编辑器：写文章、拖图片（**不会**生成网站） |
| **2** | **看效果** | **改完东西必点**：清理 + 重新生成 + 自动打开浏览器预览 |
| **3** | 发布上线 | 满意了传到线上；传失败也能「只重传」（见 8.2） |
| **4** | 先备份 | 动手删东西 / 换图片之前，先留个底（进 `backup\日期时间\`） |
| **5** | **撤回改动** | 改坏了？一步回到上次能用的样子 |
| **6** | 全面自检 | 查断链 / 没渲染的标签 / 重复 id / 图片体积 |
| **7** | 其他功能 | 里面还有两个：`[1]` 开预览、`[2]` 更新歌单（平时不用点，需要时进去选） |
| **0** | 退出 | 干完活关掉它 |

**日常只记三个数字：改东西用 `1`，看效果用 `2`，满意了按 `3`。**
`6` 自检、`7` 里的开预览都是「需要时才用」，不用背（见下面问题二）。

### 0.1 三个最容易搞混的问题

**问题一：改东西用 HexoHub，还是用这个脚本？**

> **改内容用 `1`（HexoHub），让改动「生效」用 `2`。** 两者不冲突：

| 你想干的事 | 用哪里 | 为什么 |
|---|---|---|
| 写文章、改文章、插图片、批量改标签、删文章 | **`1`（HexoHub）** | 只有它有编辑器 |
| 改网名、自我介绍、首页句子、待办、游戏清单、歌单 | **记事本** | 这些是 `source\_data\` 下的数据文件（见第 6 节），HexoHub 管不到 |
| 让改动「生效」 | **`2`** | Hexo 不会自动感应，必须重新生成 |
| 生成 + 上传一条龙 | **`3`** | 它就是「清理 → 生成 → 上传」 |

> HexoHub 里的【清理】【生成】【部署】按钮和菜单 `2`、`3` 干的是同一件事。
> **建议用菜单**：它会检查预览有没有开着、每一步成没成功，出错时告诉你失败在哪一步；HexoHub 的按钮不会。

**问题二：本地预览在哪儿？**

> **别记端口号，按 `2` 就行。** 两个地址：
>
> - `http://localhost:4000/` —— 你在 **HexoHub 里**点【启动服务器】时用的
> - `http://127.0.0.1:4010/` —— **菜单 `2` / `7` → `[1]`** 自己起的预览
>
> ⚠️ **两个预览不要同时开**：HexoHub 发现 4000 被占会杀掉占用进程，而生成前会先删掉 `public\`，
> 两边同时动就是「构建成功但网站没了」。菜单起的预览窗口**不要关**，关掉就等于关掉预览。
> ⚠️ **别双击 `public\index.html` 看效果** —— 资源是绝对路径，用 `file://` 打开图全没了。

**问题二·补：写文章时想边写边看图，怎么办？**

> **别指望编辑器里的「预览」**。HexoHub 的编辑器预览是把 Markdown 重新渲染一遍，
> 它**不读磁盘上的图片**，也不认 Hexo 的标签 —— 所以正文里的图一律显示不出来。
> 换 VS Code、Typora 也一样，任何 Markdown 预览器都有这个问题。
>
> **正确姿势：菜单按 `7` → `[1]` 开预览，然后浏览器刷新看。**
>
> | 步骤 | 做什么 |
> |---|---|
> | 1 | 菜单按 `7` → `[1]` —— 只启动预览服务器（不重新生成），秒开 |
> | 2 | 把 `http://127.0.0.1:4010/` 存进浏览器收藏夹 |
> | 3 | 在 HexoHub 里写文章、拖图片，`Ctrl + S` 保存 |
> | 4 | **回到菜单按 `2` 重新生成**（这一步省不掉，见下），再刷新浏览器 |
>
> > ⚠️ **实测澄清：`hexo server` 的「热重载」在本机不生效。**
> > 2026-10 实测：改完 `source\_posts\*.md` 后盯着服务器日志等 30 秒，
> > 日志一行都没有（只有启动时那三行），页面标题始终是旧值。
> > 也就是说它**只服务启动那一刻生成的快照** —— 改内容必须按 `2` 重新生成。
> >
> > **开预览**仍然值得用，但价值在于：**不用每次都关掉预览、重启服务器**，
> > 它的启动比 `2` 快且不重新生成，适合「先把站点挂起来、边写边看结构」。
> > 真要看到内容更新，仍然是 `2` + 刷新。
> >
> > 关于图片：图片是**改一次、长期不变**的，放进 `source\images\` 后按一次 `2`，
> > 之后就一直看得见了 —— 所以「边写边看图」实际只卡在第一次。
>
> **如果你要在 HexoHub 内部看**：设置 → 「预览模式」选**「服务器预览」**，
> 再把「iframe地址获取方式」选成**「根地址」**。
> ⚠️ **不要选「Hexo标准地址」** —— 它会拼出 `/年/月/日/标题/` 这种地址，
> 而本站 `permalink` 是 `:title/`（不含日期），选了必定报 `Cannot GET`。

**问题三：按了发布，线上却没变？**

> 按顺序查这三条，基本一步就能定位：
>
> 1. **发布窗口最后一行是不是 `✓ 完成`？** 不是的话看它指出的失败步骤。最常见的两种：
>    - **提示 4000 端口被占用**：HexoHub 的预览开着会打断构建 → **按提示停掉它**。
>    - **`TLS connect error` / `unable to access`**：本机代理（Clash Verge）掉了。
>      **内容没丢**，重新按 `3` 选 **[1] 只重传** 即可。
> 2. **GitHub 还要 30–120 秒**才发布完，用 `Ctrl + F5` 强制刷新。
> 3. 想确认到底传上去没有：按 `6` 自检，或看 8.2 末尾的办法。

### 0.2 完整一圈长这样

```
  ① 菜单按 1  写点东西            （或用记事本改 source\_data 里的文件）
                 ↓
  ② 菜单按 2  看效果              ← 不满意就回到 ①
                 ↓
  ③ 菜单按 3  发布上线
                 ↓
  ④ 打开 https://Jawooth.github.io/  按 Ctrl+F5
```

> 写**带图**的文章时，中途改用 `7` → `[1]`：菜单按 `7` → `[1]` 常驻预览 → 边写边在浏览器看结构 →
> 每次改完内容仍要回菜单按 `2` 重新生成（`7` → `[1]` 起的预览**不含**热重载，见 8.1）→ 定稿后再按 `2` 走一遍完整流程。

**唯一要养成的习惯：动文章或图片之前，先按 `4` 备份一次。**

### 0.3 命令行写法对照（给 AI 与爱折腾的人）

| 命令行写法 | 等于菜单 |
|---|---|
| `npm run build`（= `hexo clean && hexo generate`） | `2` |
| `npx hexo server` / `npm run server` | `7` → `[1]` 开的预览（`http://127.0.0.1:4010/`） |
| `npx hexo deploy` | `3` → `[2] 重建并上传` |
| 只推现成结果 | `3` → `[1] 只重传` |
| 备份 / `git checkout -- .` | `4` / `5` |
| `py -3 tools\fetch\fetch-netease.py` / `py -3 tools\check\verify-site.py` | `7` → `[2]` / `6` |

命令都写在 `package.json` 里（`build` / `generate` / `server` / `deploy`）：**给 AI 可以直接写命令**（第 12 节），你自己只走菜单。

> **Python 一律写 `py -3`**：输入 `python` 只会提示 `Python was not found`（微软商店占位程序）。
> 本站用到的两个库是 `PyYAML`（自检查数据文件）和 `Pillow`（图片工具），本机已装好。

## 1. 我想改什么，该动哪里

### 1.1 在 HexoHub 里点几下就能改的（菜单 `1`）

HexoHub 是这个博客的「操作面板」，管**文章 + 图片 + 生成上传**三件事
（MIT 开源：<https://github.com/forever218/HexoHub>，装在仓库外 `D:\tools\HexoHub\hexohub.exe`，不会被发布出去）。

| 我想… | 在 HexoHub 里怎么点 |
|---|---|
| 写一篇新文章 | 点 **+**（或【创建新文章】）→ 填标题 → 写正文 |
| 改一篇已有文章 | 左边列表里点它 → 直接改（`Ctrl + S` 保存）→ 切到「预览」看效果 |
| 文章里插一张图 | 把图片文件**直接拖进编辑框**（自动放好图片并填上引用，见 2.3） |
| 按标签 / 分类找文章 | 列表上方的「按标签 / 按分类」筛选，或用左侧标签云 |
| 一次给多篇加标签 / 删多篇 | 列表里勾选（可全选）→【添加标签】【添加分类】【删除】 |
| 改网站名字、描述、作者 | 【配置】→ 基本设置（写进 `_config.yml`） |
| 看命令成功还是失败 | 【查看日志】（✓ 成功 / ✗ 失败与错误详情） |

**HexoHub 能碰到哪些文件（很重要）**：

- ✅ 文章 `source\_posts\*.md`（新建、编辑、批量改标签、删除）
- ✅ 拖进编辑器的图片（复制到 `source\_posts\<文章名>\`）
- ✅ 站点主配置 `_config.yml`
- ❌ **不碰** `source\_data\*.yml`（网名、句子、待办、清单、歌单都在这里）
- ❌ **不碰** `_config.minimalism.yml`（导航菜单、页脚图标）
- ❌ **不碰** `source\css\`、`scripts\`、`themes\`（样式、脚本、模板）

> ⚠️ **HexoHub 里的「预览」看不到文章的图** —— 它只是把 Markdown 重新渲染一遍，
> 不读磁盘上的图片、也不认 Hexo 标签。要看带图效果，用**菜单 `7` → `[1]` + 浏览器**（见上文「问题二·补」）。
> 想在 HexoHub 内部看：设置 → 预览模式 →「服务器预览」→「iframe地址获取方式」选**「根地址」**。

### 1.2 要用记事本改的（`source\_data\` 数据文件）

这些是「数据文件」，格式简单、每行都有中文注释，**只改冒号后面或引号里的字，不要动冒号和缩进**。
每个字段能填什么、写错会怎样，见**第 6 节**。

| 我想改… | 用记事本打开这个文件 |
|---|---|
| **网名、头像路径、自我介绍、社交图标** | `source\_data\profile.yml` |
| **首页便签上轮换的句子** | `source\_data\quotes.yml`（两侧的「」也能换掉或去掉） |
| **首页两侧的装饰图**（张数 / 哪侧 / 固定位置或随机 / 宽度） | `source\_data\decor.yml` |
| **闲置屏保**（触发秒数 / 泡泡数 / 提示文字） | 根目录 `_config.yml` 的 `screensaver:` 段 |
| **待办清单**（文字页侧栏 + 首页数字） | `source\_data\todo.yml` |
| **游戏 / 工具卡片**（游戏页） | `source\_data\apps.yml` |
| **播放器的曲目、窗口标题** | `source\_data\music.yml`（换网易云歌单后按 `7` → `[2]`） |
| **作品页的栏目与分期** | `source\_data\works.yml` |
| **关机彩蛋的文字**（错误弹窗 / 蓝屏） | `_config.yml` 的 `shutdown:` 段（见 **7.1**） |
| 头像 / 壁纸 / 作品图 | 直接**覆盖** `source\images\` 里的同名图片（见第 3 节） |
| 导航菜单、页脚图标 | `_config.minimalism.yml`（**进阶**，改前先按 `4` 备份，见第 7 节） |

> **怎么用记事本打开？** 文件上**右键 → 打开方式 → 记事本**。存盘直接「文件 → 保存」，
> **不要**另存成 `.txt`。
> ⚠️ **别用 PowerShell 命令去批量改中文文件**（会把中文变成 `?`）；改中文文件就用记事本，或让 AI 助手改。

### 1.4 图标地图：每个图标在哪改

站里的图标分两类：**图片文件**（覆盖同名文件就行）和**内置矢量图形**（写在代码里）。

| 图标 | 在哪改 | 说明 |
|---|---|---|
| 浏览器标签页图标 | 覆盖 `source\favicon.ico` | 32×32 或 48×48，见 3.1 |
| 站长头像 | `profile.yml` 的 `avatar`，或覆盖 `source\images\site-avatar.png` | 见 3.1 / 6.1 |
| 头像下方一排社交图标 | **显示哪些**：`profile.yml` 的 `contacts`（填链接就出现，留空隐藏）；**图标形状**：`scripts\xp-content.js` 搜 `PROFILE_ICONS` | 形状是内置的各平台官方标志，一般不用动 |
| 页面最底部那排社交图标 | `_config.minimalism.yml` 的 `contact:` 段 | 和头像下那排是**两套**，互不影响 |
| 首页窗口标题栏的小图标 | **形状**：`scripts\xp-icons.js` 的 `GLYPHS`（IconPark 平滑多色 SVG body，重着色表在 `tools\icons\park-recolor.js` 的 `TINT`，语义映射在 `tools\icons\park-map.js`）；**用哪个**：页面里 `include('xp-window-title', { title: '…', icon: 'clipboard' })` 的 `icon` 参数 | 标题图标是 `<svg><use href="#icon-clipboard">` 引用同一份矢量；换图形改 `park-map.js` 映射，换配色改 `TINT`，改完跑 `node tools/icons/emit-smooth.js` + `node tools/icons/merge-smooth-xp-icons.js` 再生成 |
| 顶部导航菜单 | `_config.minimalism.yml` 的 `menu:` 段 | 纯文字项，没有图标 |

> ⚠️ **标题图标、任务栏/开始菜单图标、分类页与标签页的标签图标，三处用的是同一批矢量**
> （`scripts\xp-icons.js` 的 `GLYPHS` = IconPark（Apache 2.0）平滑多色 SVG，经 18 键色板重着色；
> 分别由 `xp-enhance.js` / `xp-taskbar.js` / 标签页读取）。
> 改一处三处同步；这也是为什么不要再在任何页面里手抄 SVG 图标。
>
> ⚠️ 动过 `scripts\` 或 `themes\` 之后，普通生成**不会**带上新改动（构建有缓存），
> 必须走一次清理：菜单按 `2`（自带清理）。

### 1.5 窗口标题文字在哪改

每个 XP 窗口的标题文字，都写在 **`<span class="xp-window-title-text">` 里面、图标 `<svg>` 之后**。
现在标题整行由 `themes\minimalism\layout\includes\xp-window-title.ejs` 统一渲染，页面里只写一行：

```ejs
<%- include('./includes/xp-window-title', { title: '详细属性', icon: 'clipboard', buttons: false }) %>
```

- **只改文字**：改 `title:` 的引号内容（比如把 `最近作品` 改成 `我的作品`）。
- **换左侧小图标**：改 `icon:` 的值，取值是 `scripts\xp-icons.js` 里 `GLYPHS` 的键去掉 `icon-` 前缀
  （`clipboard` / `post` / `tag` / `palette` / `chart` / `compass` / `search` / `pencil` / `clock` /
  `gamepad` / `wrench` / `image` / `fallback`，导航类另有 `nav-home` 等）。
- **不要手写或手改 `<svg>`**：那个 `<svg><use href="#icon-…"></svg>` 是 include 生成的，
  手改会被下一次生成覆盖，形状真源始终是 `scripts\xp-icons.js`。

| 窗口标题 | 改哪个文件 |
|---|---|
| 首页全部窗口（`用户账户`、`最近作品`、`标签云`…） | `source\index.md` |
| 作品页（`我的作品集`、`创作统计`…） | `source\works\index.md` |
| 游戏页顶部标题 | `source\games\index.md` |
| 分类页 / 标签页顶部（`全部分类` / `全部标签`） | `source\categories\index.md` / `source\tags\index.md` |

**两处例外（是脚本生成的，不在上面文件里）**：

| 标题 | 改哪里 |
|---|---|
| 游戏页分组标题条（`小游戏 (3)`、`小工具 (3)`） | `scripts\xp-content.js` 的 `appsGrid()`，搜 `label: '小游戏'`（括号里数字自动统计，别手写） |
| 文字页主标题 `文字 · 全部文章` | `themes\minimalism\layout\index.ejs` 第 10 行 |
| 文字页 / 各页侧栏 6 个窗口（`最近文章`、`标签云`、`小站数据`、`关于我`、`浏览`、`争取在死之前做完`） | `scripts\xp-content.js` 搜 `widget('…')`，改第一个参数 |

> ⚠️ 侧栏那 6 个窗口标题是**全站共用**的：改一次，文章页、归档页、分类页、标签页的侧栏会一起变。
> 想只让文字页不一样，得单独改（进阶，改前先按 `4` 备份）。
>
> ⚠️ 浏览器标签页上显示的 `文字` 来自 `themes\minimalism\layout\includes\head.ejs` 第 29 行，
> 和窗口标题是**两回事**。

**注意**：标题里的**文字可以随便改**，但 `xp-window-title-text` 这个 class 一旦去掉，
标题栏样式（蓝底白字、字体）就失效了。同一句话在文件里可能出现多次（例如 `作品集` 既是作品页标题
也在导航菜单里），改之前看清楚是不是你要的那个窗口。

## 2. 写一篇文章

### 2.1 在 HexoHub 里写

1. 菜单按 `1` 打开 HexoHub（第一次让它打开博客目录 `D:\tools\hexo`，之后会记住）
2. 点 **+** /【创建新文章】，填：**标题**（必填，可中文）、**标签**（输入后回车）、
   **分类**（回车）、**摘要**（可选，显示在卡片上）
3. 写正文（工具栏有现成按钮：【标题 1/2/3】【粗体】【引用】【表格】【代码块】…）
4. **写完按 `Ctrl + S` 保存**，然后回到菜单按 `2` 看效果

> 新建文章会读 `scaffolds\post.md` 当模板，最上面那段注释是字段提示（不会出现在网站上，嫌占地方可删）。

### 2.2 正文排版速查（Markdown 就这几招）

正文就是普通写字，想加效果时才用下面这几个符号（都是**英文符号**）。
**每行顶格写**，段落之间空一行：

| 想要的效果 | 就这么写 | 长什么样 |
|---|---|---|
| 大标题 / 小标题 | `# 标题`（# 后面有空格；## 更小一级） | 加大加粗的字 |
| **粗体** | `**这两个字**` | 这两个字变粗 |
| ~~删除线~~ | `~~这几个字~~` | 中间划一道线 |
| 列表 | 每行开头加 `- `（减号 + 空格） | 一条条排下来 |
| 引用别人的话 | 行开头加 `> ` | 整段左边多一条竖线 |
| 分隔线 | 单独一行写 `---` | 一条横线 |
| 链到别的网页 | `[显示的字](https://网址)` | 点了就跳过去 |
| 链到自己另一篇文章 | `{% post_link 那篇的文件名 %}` | 见 2.5 |
| 插图片 | 把图片文件**拖进编辑框** | 见 2.3 |

最容易踩的坑就两个：从别处**粘贴**时把行前空格也带进来（缩进 4 空格的行会被当成灰底代码块，
整段排版全毁）；符号用了**中文全角**（`＃＊～` 不生效，要英文 `# * ~`）。

### 2.3 正文里插图

**把图片文件直接拖进编辑框**就行：HexoHub 会自动把图复制到 `source\_posts\<文章名>\`，
并插好 `{% asset_img 文件名 "描述" %}` 引用。

**一件作品里放多张图，推荐这样安排**：

1. **当封面 / 主图的那张走脚本导入**（见 3.2）—— 自动有压缩、缩略图、封面
2. **其余的图直接拖进正文**，一张一张拖，想放几张放几张
3. 想精确控制就把图放进 `source\images\works\`，正文里用 Markdown 图片语法引用：
   英文叹号 `!` + 方括号里的描述 + 圆括号里的路径（如 `/images/works/图名.jpg`）

拖进正文的图**原样复制、不压缩**（大图先自己压一压）。透明底 PNG 在正文里放心用 ——
浏览器认透明，**不会**被铺白底（铺白只发生在「作品主图存成 JPG」那一步，见 3.4）。
⚠️ 正文插图**不会**自动变成卡片封面，封面要写 front matter，见 3.4。

> ⚠️ **拖进来的图，在 HexoHub 的「预览」里看不见** —— 那是 Markdown 渲染器，不读磁盘图片。
> 图放对了也一片空白，别以为拖失败了。**按菜单 `7` → `[1]` 开浏览器预览**（见上文「问题二·补」），
> 浏览器刷新就能看到。

### 2.4 文章最上面那段（front matter）怎么填

普通文章这样写就够了：

```yaml
---
title: 我的第一张板绘        # 标题
date: 2026-10-11 20:00:00   # 日期，决定排序和分期
tags: [板绘, 练习]           # 标签
---
```

如果这是一件**作品**（要出现在作品页），再加上这几行：

```yaml
---
title: 风景插画·山间小屋
date: 2026-09-28 14:30:00
categories: [作品, 插画]     # 第一个必须是「作品」，后面的变成分类标签
origin: 原创                # 原创 或 同人（决定作品页栏目）
tags: [风景, 数码绘画]
short_title: 山间小屋        # 卡片上的短标题（不填用 title）
desc: 一句话简介，显示在卡片和最近作品里
img: /images/works/landscape.jpg             # 分享卡片图（og:image）
thumbnail: /images/works/landscape-thumb.jpg # 卡片封面（-thumb 小图省流量）
status: done                # done = 已完成；doing = 进行中（卡片角标）
---
```

**字段速查**（不填会怎样）：

| 字段 | 能填 | 不填 → |
|---|---|---|
| `title` | 任意文字 | 拿文件名当标题 |
| `date` | `2026-10-11 20:00:00` | 文件名日期 → 创建时间；决定**排序**与**分期** |
| `tags` / `categories` | `[随笔]` 或 `[作品, 插画]` | 标签云无此词 / 不算作品 |
| `desc` | 一句话 | 取正文第一段（超 96 字截成 `…`） |
| `img` | `/images/works/xxx.jpg` | 分享卡片无图（**文章页已不再显示顶部大图**，2026-10-18 瀑布流改版时移除） |
| `thumbnail` | `/images/works/xxx-thumb.jpg` | 卡片退回用 `img`；**首页「最近作品」没它整卡不出现** |
| `permalink` | `my-slug`（网址变 `/my-slug/`） | 用文件名当网址（见 2.6） |
| `sticky` | 数字，越大越靠前 | `0`（只影响 `/blog/` 置顶，卡片标题右侧带「到顶」箭头） |
| `password` | 密码字符串（有前导 0 必须加引号） | 不加密码（见第 5 节） |
| `hide` | **只写 `true` / `false`** | 不隐藏（只让它从 `/blog/` 列表消失） |
| `origin` | **只有 `原创` / `同人`** | 按 `原创` |
| `era` | 分期名（如 `2025 年`） | 按 `date` 自动归入 |
| `status` | **只有 `doing` 有特殊效果** | 算已完成（绿点） |
| `short_title` | 短标题 | 用 `title` |

**三条最容易踩的规则**：

1. **作品必须写 `categories: [作品, …]`**。少了「作品」两个字，这篇就从作品页和首页
   「最近作品」消失 —— **不会报错**，只是没了。
2. **`origin` 只能填 `原创` 或 `同人`**（这两个词在 `source\_data\works.yml` 里能改）。
3. **文件名决定网址**（规则是 `/文件名/`，不带日期）。中文文件名 = 中文网址（能用，只是复制
   出来是一串 `%E5%85%B3...`）。想要英文短网址就加 `permalink: my-slug`（见 2.6）。

> **时间轴分期不用管**：按 `date` 自动归入；想手动指定加 `era: 2025 年`
> （必须与 `works.yml` 里的分期名完全一致，否则排到最后）。
>
> ⚠️ front matter 是 YAML：**语法写错 → 构建直接失败**（改回来就好）；**字段值写错
> （如 `origin: 原創`）→ 不报错，静默回默认值** —— 所以改完一定按 `2` 看效果。

### 2.5 文章之间怎么互链

用 `{% post_link %}`（构建时算好网址，以后改文件名不会断链）：

```text
{% post_link work-landscape-cottage %}            链接文字自动用那篇的标题
{% post_link work-landscape-cottage 这个作品 %}    自己指定显示文字
{% post_link "Hello World" %}                     标题里有空格就加英文引号
```

参数填**文件名（去掉 `.md`）或标题**；**不要填 `permalink` 的值** —— post_link 认的是文件名，
不认短网址（填了会报 `Post not found`）。目标不存在时**构建直接报错**（好事，不会留悄悄的断链）。

### 2.6 自定义文章网址（permalink）

**默认规则**：网址 = `/文件名/`（`work-sunset.md` → `/work-sunset/`），所以 2.4 一直建议文件名用英文。
想给某篇文章换更短的网址，在它的 front matter 加一行：

```yaml
---
permalink: landscape      # 网址就从 /work-sunset/ 变成 /landscape/
---
```

**四条规则**（都有自检 / 构建兜底，按 `6` 能查出来）：

1. **已发布过的文章再改 `permalink` 就是换网址**：旧链接立刻 404（搜索引擎收录的、别人收藏的都算），
   拿不准别动；**还没发布过的随便改**。
2. **不能和已有页面重名**（`works`、`blog`、`tags` 这些顶层名字），两篇文章之间也不能重名 —— 重了构建直接报错。
3. **只填英文 / 数字 / 短横线**；中文能跑，但复制出去是一串 `%E5%85%B3...`，不推荐。
4. **互链不认它**：`{% post_link %}` 永远填文件名或标题（见 2.5）。

## 3. 图片：换图、封面、批量导入

### 3.1 换头像 / 壁纸 / 图标：覆盖同名文件

| 想换什么 | 覆盖这个文件 | 建议 |
|---|---|---|
| 头像 | `source\images\site-avatar.png` | 正方形 256×256 |
| 浅色壁纸 | `source\images\xp-desktop-bg.webp` | 2560×1600；2026-10-19 起用 webp（同画质体积只有 png 的 1/6） |

> **站标 favicon 怎么重画的**：`tools\images\make-favicon.py` 从 iconfont 的「像素兔子」字形
> 渲染出 16 / 32 / 48 三档，一起打包进 `favicon.ico`（三档都要：标签页用 16、
> 任务栏书签用 32、桌面快捷方式要 48，只做一档系统会自己缩放、小图标会糊）。
> 那个 `iconfont.ttf` **没有进仓库**（iconfont.cn 的图标协议各异、下载包也没附授权文件，
> 无法确认能否再分发），所以仓库里只留生成好的 .ico。要重画就把字体放到
> `D:\Download\font_zxvd6j58ddp\iconfont.ttf` 或 `tools\images\iconfont.ttf`；
> 找不到字体时脚本会提示并**直接退出、不动现有站标**。
>
> 另外：`tools\images\make-assets.py` 以前也生成 favicon（旧的"蓝窗口"设计），
> 2026-10-15 已把那段移出 —— 否则跑一次它就会把兔子站标覆盖回旧设计。

> ⚠️ 头像文件名固定叫 `site-avatar.png`，别改成别的名字 —— 主题配置、数据文件、脚本三处的默认值都指向它。
>
> **首页两侧装饰图**：图放进 `source\images\decor\`（png / gif 动图 / webp / jpg 都行，**文件名随意**），
> 然后在 `source\_data\decor.yml` 的 `items:` 下加一行，四样随便配：贴哪侧（`side: left` 或 `right`）、
> 距窗口顶多远（`top: 120px`，也能写 `30%`）、显示宽度（`width: 160`）。
> **随机位置模式**（2026-10-19 新增）：把 `top` 换成 `random: true`，这张图就不再写死位置 ——
> **每次刷新**在窗口两侧随机换地方，且同侧几张图自动分段错开、不会叠在一起；
> 随机脚本是构建时自动注入的 `public/js/xp-decor-random.js`（改 decor.yml 就行，不用碰它）。
> 想贴几张贴几张，删一行就是撤一张；全清空两侧就不显示。
> **只在窗口 ≥1500px 的大屏显示**（窄屏自动隐藏）—— 预览时看不到，先把浏览器窗口拉宽再找原因。

> **闲置屏保**（2026-10-19 新增）：约 60 秒无操作，全屏浮起深色层 + 一串彩色大泡泡屏内漂浮（互不重叠）；
> 任意键 / 点击 / 触摸 / 滚轮 / 滑动退出。行为在根目录 `_config.yml` 的 `screensaver:` 段配（没有这段就用默认值）：
> `idle_seconds` 触发秒数、`bubbles` 泡泡数量（上限 40，大小 80–200px 随机）、
> `tip` 底部提示文字（**只显示一次**，之后记住交互不再出字；想再看到就清浏览器缓存）。
> 深度用户注意：屏保脚本 `scripts/xp-screensaver.js` 是构建期把配置烙进 JS 的（改配置要重新 `hexo generate`）；
> `prefers-reduced-motion` 用户不触发。

### 3.2 传图全流程

#### 第一步：先搞懂 front matter 是什么

**front matter = 文章最上面、被两行 `---` 夹住的那段「文章属性」**。它不显示在页面上，
但决定了这篇归到哪、卡片长什么样、网址是什么：

```markdown
---
title: 风景插画·山间小屋      ← 标题
date: 2026-09-28 14:30:00     ← 日期（决定排序和时间轴分期）
categories: [作品, 插画]       ← 分类；写 [作品, xxx] 就是一件作品
origin: 原创                  ← 作品栏目：原创 / 同人
tags: [风景, 数码绘画]         ← 标签（作品页的筛选按钮由它生成）
desc: 一幅山间小屋的风景插画    ← 卡片上那句话简介
thumbnail: /images/works/x-thumb.jpg   ← 卡片封面
img: /images/works/x-800.jpg           ← 分享卡片图（og:image）
status: done                  ← done 已完成 / doing 进行中
---

正文从这行下面开始写……
```

字段逐项说明见 **2.4**。**你不需要手写它** —— 下面两个脚本都会自动填好。

#### 第二步：选一条路径

| 你的情况 | 用哪个 | 它做什么 |
|---|---|---|
| **一次导入一整个文件夹**（最常用） | `import-artworks.py` | 压图 + **自动写好每篇文章** |
| 单张 / 一篇作品多张图，想自己写文章 | `make-work-images.py` | 压图 + 打印 front matter 给你贴 |

**路径 A：批量导入一整个文件夹**（含子文件夹，每张图各成一件作品）。先演练再真导：

```
py -3 tools\images\import-artworks.py "D:\我的画" --dry-run     ← 先看计划，不写任何文件
py -3 tools\images\import-artworks.py "D:\我的画"               ← 确认没问题再真导
```

**每张图做四件事**：

1. 生成三档尺寸、每档 **WebP + JPEG 两份**（见下面的尺寸表）
2. 原图备份到 `backup\images-original\works\`（**不会丢原图**）
3. **直接写好 `source\_posts\work-<短名>.md`** —— front matter 和正文都填好，图已引好
4. 跑完打印体积统计（仓库占用 / 访客实际下载）

常用选项：

| 参数 | 作用 |
|---|---|
| `--category 插画` | 作品子分类（默认「插画」，决定作品页筛选按钮） |
| `--origin 原创` / `--origin 同人` | 作品页栏目（默认「原创」） |
| `--tags "风景,数码绘画"` | 标签，逗号分隔 |
| `--desc "一句话"` | 简介（这一批共用；想单独写，导入后改那篇的 front matter） |
| `--no-large` | 不生成 1600 大图（省体积） |
| `--force` | 已存在的同名作品也覆盖 |
| `--dry-run` | 只看计划，不写任何文件 |

> **日期**：优先取照片的 EXIF 拍摄时间，没有就用文件修改时间 —— 作品页时间轴按日期分期。

**路径 B：单张 / 一篇多图**

```
py -3 tools\images\make-work-images.py "D:\我的画\山间小屋.png" landscape-cottage     ← 单张
py -3 tools\images\make-work-images.py "过程1.png" "过程2.png" process                ← 多张（自动编号 process、process-2…）
py -3 tools\images\make-work-images.py "x.png" x --dry-run                           ← 先看计划
```

**这个脚本不写文章文件**，跑完会打印：可直接粘贴的 `<picture>` 代码（放进正文）、
以及 front matter 该填的 `thumbnail:` 和 `img:` 两行。然后自己建文章（菜单 `1`，或
`npx hexo new post "标题"`），把上面的东西贴进去。

> **短名（slug）= 网址**：文件名尽量用英文（`sunset.png` → `/work-sunset/`）。
> 纯中文文件名没法自动转英文，脚本会用 `work-<哈希>` 兜底并**列出来提醒你**，
> 想改就导入后改文件名，或加一行 `permalink:`（见 2.6）。

#### 两个脚本共用的图片规格

三档尺寸，每档都是 **WebP + JPEG 两份**（浏览器自动挑 WebP，老旧浏览器回退 JPEG）：

| 档位 | 尺寸 | 用途 |
|---|---|---|
| 中图 | 最长边 **800**（保持原比例） | 正文里显示的那张 |
| 大图 | 最长边 **1600**（保持原比例） | 想「点开放大」时用（`--no-large` 可关） |
| 缩略图 | **480×360**（居中裁成 4:3） | 卡片封面（默认） |

**为什么缩略图是 4:3、中图不裁**：作品页是瀑布流（2026-10-18 站主定稿），
封面按图片**实际比例**显示、不会被 CSS 裁切 —— 任何比例的封面图都能完整展示。
缩略图统一裁成 4:3 只是给脚本导入的作品一个**整齐的默认封面**（横竖构图在瀑布流里高度一致）；
不想要这个效果，就在 front matter 把 `thumbnail:` 指向原比例的图（比如 `img:` 那张），
瀑布流会原样显示它的高低错落。正文用的中图 / 大图始终保持原始比例，不会变形。

**效果（实测一张 16.75 MB 的原图）**：访客实际只下载 **约 486 KB**（WebP 那一份），压到原来的 **2.8%**。
清晰度按「长边 800 / 1600」保留，正常浏览距离下看不出差别。**100 张作品估算约 47 MB**，
远在 GitHub Pages 的 1 GB 限制内。

#### 自动处理的三件容易翻车的事

两个脚本都会处理，不用你操心：手机照片按 **EXIF 方向位自动摆正**（否则横竖颠倒）；
**透明底 PNG 自动铺白底**（否则存成 JPG 后透明区域变黑）；
标题 / 简介里的**特殊字符自动加引号**（否则 YAML 写错，构建直接失败）。

#### 封面裁得不理想怎么办

原图备份在 `backup\images-original\works\`，**随时可以重来**：

- **重新跑一次**脚本即可（缩略图会重新生成）；
- 想让默认封面的裁剪更靠上 / 靠下：改 `tools\images\work_images.py` 里的 `THUMB_TOP_BIAS`（默认 `0.38`，越小越偏上）；
- 瀑布流不裁封面：**嫌弃 4:3 默认封面的话根本不用裁**——把 `thumbnail:` 改成指向 `img:` 的原图（或任何比例的图），瀑布流按实际比例完整显示。

#### 想彻底删掉某个作品

图在 `source\images\works\<短名>-*`，文章在 `source\_posts\work-<短名>.md`，**两处都删**
再重新生成即可。原图仍留在 `backup\` 里。

#### 怎么确认图真的放对了

⚠️ **不要用 HexoHub 的「预览」检查** —— 它不读磁盘图片，路径写对了也是空白（见上文「问题二·补」）。

**正确做法**：菜单按 `7` → `[1]` 开预览 → 浏览器打开 `http://127.0.0.1:4010/works/` → 刷新。
看到卡片封面 = 导入成功。点进文章页再确认一遍正文里的图。

如果浏览器里也看不到，按顺序查：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 卡片是灰底空框 | `thumbnail:` 路径写错或文件没生成 | 看 `source\images\works\` 里有没有 `<短名>-thumb.jpg` |
| 分享出去没有图 | `img:` 路径写错 | 同上，找 `<短名>-800.jpg`；只影响分享卡片，页面本身照常 |
| 正文里的图不显示 | 图不在文章资源夹里 | 确认图在 `source\_posts\<文章名>\` 下，且引用写的是**文件名**不是完整路径 |
| 改了图但页面没变 | 浏览器缓存 | `Ctrl + F5` 强制刷新 |
| 全站都乱了 | 文件名含中文导致网址异常 | 按 `6` 自检，看它列出的问题文件名 |

#### 为什么图片逻辑只有一个文件（改脚本的人看）

图片处理逻辑**只有一份**，在 `tools\images\work_images.py`；上面两个脚本都调用它。
想改尺寸、质量、裁剪方式，改那一个文件就够，不会出现「两个脚本行为不一致」。

跑完记得**菜单按 `2`** 看效果。

### 3.3 哪些图会被自动处理？（边界说清楚）

「尺寸、方向、透明底**一定会**被自动调节吗」—— **只有走脚本的作品图才有这个保证**：

| 这张图怎么来的 | 方向摆正 | 透明铺白 | 压缩 |
|---|---|---|---|
| 脚本导入（3.2） | ✅ 一定 | ✅ 一定 | ✅ 中图 800 / 大图 1600 / 默认缩略图 4:3 |
| HexoHub 拖进正文（2.3） | 原样 | 原样 | ❌ 不压缩 |
| 手动覆盖头像 / 壁纸（3.1） | 原样 | 原样 | ❌ |
| 手动放进 `source\images\works\`（3.4） | 原样 | 原样 | ❌ |

一句话：**脚本处理的图它负责到底；绕开脚本的图它一个字节都不碰。**

### 3.4 想自定义封面怎么安排

**封面只认 front matter 的两个字段，正文里插的图永远不会自动变成封面**：

| 字段 | 用在哪 | 没写 → |
|---|---|---|
| `thumbnail:` | **卡片封面**（首页「最近作品」、作品页卡片、分享小图） | 退回用 `img:`；**首页「最近作品」没它整卡不出现** |
| `img:` | **分享大图**（og:image），兼作 `thumbnail` 的兜底 | 分享卡片没图 |

**给作品换 / 自定义封面（三步）**：

1. 把想当封面的图放进 `source\images\works\`（**比例随意** —— 瀑布流按实际比例显示，不裁切；
   想和脚本默认封面观感一致就用 4:3、480×360 左右）
2. 打开那篇文章的 front matter，加一行：`thumbnail: /images/works/你的图.jpg`
3. 菜单按 `2` 看效果

**封面可以和正文第一张图不一样**：封面走 `thumbnail:`，正文随便放 —— 很适合「用一张局部当封面，
正文放全图」。用 3.2 脚本导入的作品会自带 `-thumb.webp` / `-thumb.jpg` 当封面；想换成别的图，
把新图放进去、改 `thumbnail:` 指向它即可。

## 4. 作品里放视频

页面里只写一行标签（样式和样板都藏在标签里，不用手写 iframe）：

```text
{% xp_bilibili BV1xx411c7mD %}        ← 哔哩哔哩（推荐）
{% xp_bilibili BV1xx411c7mD 2 %}      ← 第 2 个分 P；粘整条链接也行，会自动读 ?p=2
{% xp_video /videos/clip.mp4 %}       ← 本地视频（可再跟一个参数当封面图）
```

文章和作品页都能用。**写错 BV 号会直接构建报错**（不会悄悄给你一个坏播放器）。
为什么做成标签而不是手写 HTML：iframe 没有固有尺寸，不给它一个 16:9 的盒子就会塌成 150px
或者把 XP 窗口撑破 —— 这堆东西藏在标签里最省事。

**关于体积，这是重点**：

| 做法 | 体积代价 | 建议 |
|---|---|---|
| 哔哩哔哩外链 | **0 字节**（只有一行 HTML） | **推荐**。视频存 B 站，本站不占体积。代价：要联网，封面 / 清晰度受 B 站控制 |
| 本地文件放 `source\videos\` | 有多大就多大，而且 git 会**永久保留每一版** | 只放**几 MB 的短片段** |

本地大文件为什么不行：本站是 GitHub Pages —— 仓库建议 1 GB 以内、**单文件超 100 MB 直接推不上去**
（50 MB 就警告），每次改一版 git 都把旧版本留着。整站现在才几 MB，塞一个 50 MB 的视频等于
把整站放大十几倍，首页和列表页都会跟着变慢。长视频就用 B 站外链。

> 自检不查视频：文件太大或链接失效都得自己看一眼。

## 5. 加密文章与点赞

### 5.1 给文章加密码

在**那一篇**文章的 front matter 里加一行就行，不加的文章完全不受影响：

```yaml
---
title: 某篇不想让人随便看到的文章
password: "你的密码"          # ← 必需。密码里若有前导 0，一定要加引号，否则 0710 会变成 710
message: 密码是本人生日。      # ← 可选：显示在【密码框里】的提示文字
abstract: 这篇文章被加密了。    # ← 可选：显示在【列表页卡片上】的摘要（没写 desc 时才用得上）
---
```

> ⚠️ **`message` 和 `abstract` 不是一回事，位置完全不同**：
> `message` 显示在**密码框里**（想提示密码线索就写这个）；`abstract` 显示在**列表页卡片上**
> （不写 `desc` 时才有机会显示）。想提示「密码是本人生日」，要写 **`message`**。

**效果**：打开文章 → 出现密码框，输对了才显示正文；列表页 / 首页的卡片照常显示标题和 `desc`，
只有正文被锁；卡片标题右侧和文章标题栏会出现**锁形图标**（和置顶的「到顶」箭头同一位置）；
加密文章**不显示点赞按钮**；字数统计**从源文件算**，不会变成「8 字」；
加密用的 JS（约 9.8 KB）**只有加密页才加载**。

没写 `message` 时用的全局文案，在 `_config.yml` 的 `encrypt:` 段改。

**加密强度（2026-10-22 审查补齐）**：`_config.yml` 的 `encrypt.kdf.iterations` 显式提到
`600000`（插件默认 250000，构建时会警告「低于 OWASP 建议」）。算法是
PBKDF2-HMAC-SHA256 + AES-256-GCM，参数本身没问题 —— **决定安全性的只有密码本身**：

- 构建时会对弱口令打一条 `WARN`（少于 8 位、或纯数字）。**只提醒，不会挡住构建** ——
  你若就想给随手写的东西设个「别让路过的人看见」级别的锁，4 位数字完全够用，不用改。
- 别指望 600000 轮能救弱口令。4 位纯数字只有 10000 种组合，在消费级显卡上做 PBKDF2
  爆破是**秒级**的事；把密码加到 8 位混合字符，等效空间从 10⁴ 跳到 10¹² 以上，那才是有效的一步。

**加密文章不会进站内搜索索引**（`scripts/xp-content.js` 的 `xp-search-index` 生成器）：
`/search.json` 是公开可下载的，而 hexo-blog-encrypt 渲染后 `post.content` 只剩密码框，
不过滤的话索引里会留下 `message` 那句提示语。标题/日期/分类照常入索引，
所以**搜得到标题、搜不到正文** —— 这是刻意的。`tools/check/verify-site.py` 里有对应校验。

> ⚠️ **这是「别让路过的人随便看到」级别的防护，不是真正的安全措施。**
> 正文密文会**完整下载到访客浏览器**，密码也在前端校验 —— 挡得住随手点开的人，
> **挡不住真有心想破解的人**。别用它保护敏感个人信息或任何机密。
>
> 另外：**密码明文写在 `.md` 文件里，会随文件一起进 git 仓库**。网页上是加密的，
> 但仓库若是公开的，翻源码能看到密码。想避免：用 `password: { env: 环境变量名 }`
> 从环境变量读（**注意是变量名，不是密码本身**），但要先在系统里设好那个环境变量，否则每次构建都会失败。

### 5.2 点赞

文章页底部和列表页卡片上都有点赞按钮。**点赞数只存在访客自己的浏览器里**（`localStorage`）。

**为什么不做成「所有人看到同一个数字」**：本站是 GitHub Pages **纯静态站**，没有服务端也没有数据库。
**本地点赞**（现在这样）零成本、零依赖、不收集任何信息；第三方托管（Twikoo / Waline / Gitalk）
要部署后端，开放留言还涉及 UGC 合规与备案。

**以后想换成第三方托管**：改 `scripts\xp-enhance.js` 里 `XPLikeBackend` 的 `get` / `incr`
两个方法即可（页面上已有的 `.xp-like` 结构和样式都不用动）。

> **以后要加留言板的话**：留言是用户生成内容（UGC），本站部署在 GitHub Pages（境外服务器），
> **无法完成 ICP 备案**，这是最大的合规灰区。主题**已经内置了评论接口**，只是关着：
> `_config.minimalism.yml` 的 `comment:` 段（`enable: false` → `true`，填 Twikoo 的 `envId` 即可）。
> 真要开留言，建议用第三方托管评论（如 Gitalk 走 GitHub 账号），并保持**先审后发**。

## 6. 数据文件字段速查

> ⚠️ 改这里任何文件：**关掉预览窗口 → 菜单按 `2`**。预览服务器在**启动那一刻**就把 `_data`
> 读进内存，之后改文件它不会重读 —— 「改了没生效」几乎都是这个原因，**不是你改错了**。
>
> 后果分两种：**YAML 语法错（缩进、引号）→ 构建直接失败**（改回来就好）；
> **字段值写错 → 不报错，静默用默认值或整块消失** —— 所以改完一定要按 `2` 看效果。

### 6.1 profile.yml（首页「用户账户」卡片 + 各页侧栏「关于我」）

| 字段 | 说明 / 不填 → |
|---|---|
| `avatar` | `/images/site-avatar.png`（默认值；填别的路径要保证文件真的存在） |
| `names` | 网名列表，每次打开随机取一个；第一个同时用于侧栏 |
| `name_suffix` / `name_rotate_seconds` | 标题后缀（默认 `来了！`）/ 轮换秒数，`0` = 只在刷新时随机 |
| `bio` | 侧栏简介；不填回退 `_config.yml` 的 `description` |
| `tagline` / `intro` | 首页第一段 / 正文段落（可多段） |
| `contacts.*` | 首页图标行；**没填的平台不显示**。键：`github` / `email` / `bilibili` / `xiaohongshu` / `x` / `weibo` / `pixiv` / `website` |
| `about.paragraphs` / `about.chips` | 首页底部「关于本站」段落 / 小胶囊 |

**邮箱可以走图标弹窗**：`contacts.email` 填多个带标签的地址时，首页的**信封图标**点击后弹出小窗
列出全部（弹窗顶上的说明文字取自 `about.contact_desc`）。四种写法都认 ——
`- me@example.com` · `- 个人：me@example.com` · `- {个人: me@example.com}` ·
`- {label: 个人, address: me@example.com}`（1 个地址点图标直接发信，2 个以上弹窗列出全部）。

> ⚠️ 弹窗里是可点击的完整地址（mailto），抓邮箱的机器人也能读到。想防抓取就反过来：清空
> `contacts.email`，把「名#域」写法的整句放进 `about.paragraphs`。
>
> ⚠️ **YAML 坑**：句子里出现「空格 + `#`」的话，`#` 后面整段会被当注释吞掉 ——
> 含 `#` 或「冒号 + 空格」的句子，整句用英文双引号包起来。

### 6.2 quotes.yml（首页便签）

| 字段 | 说明 / 不填 → |
|---|---|
| `rotate_seconds` | 轮换秒数；`0` = 不自动轮换（句子改为**点击首页头像**刷新，顺带触发头像弹跳和鸭叫音效） |
| `quotes` | 每项 `text`（≤60 字，格子高度固定，超了被裁）+ `from`（不填则**不显示**出处那一行） |
| `quote_left` / `quote_right` | 两侧符号，默认 `「` `」`；写 `''` 就不要符号 |

> 显示顺序是**随机**的：每次打开随机抽一句，点头像换句也是随机（且避开当前这句）。
> 列表书写顺序不影响显示。
>
> ⚠️ `quote_left: '"'` 是语法错误（引号套引号），要写 `"''"` 或用全角 `“`。
> 符号是脚本交给 CSS 画的，换符号不用碰样式。

**首页右列的计数器窗口**（标题栏是一只兔子图标）：点击头像数字 +1，次数存在访问者自己浏览器的
localStorage（键 `xp_duck_count`），清浏览器数据会归零。窗口里的文字想改就在 `source\index.md`
里搜 `xp-duck-window`（标题）或 `xp-duck-line`（正文两行）定位。窗口底部有「清除计数」按钮：
点一下变成「再点一次确认」，3 秒内再点才真的清零，超时自动恢复，防止手滑误删。

## 7. 配置文件与红线

| 文件 | 该不该改 | 能改什么 |
|---|---|---|
| `_config.yml` | 可以，只改安全项 | `title`、`subtitle`、`description`、`author`、`per_page`、`encrypt`（加密文案）、`shutdown`（关机彩蛋文案） |

**你的赢**；但主题脚本会**整个替换 `menu` 这一项**，所以导航菜单永远以后者为准。

| 项 | 注意 |
|---|---|
| `menu` | **URL 结尾的 `/` 不能省**（否则多一次 301）；每项要有 `url` 和 `name`（自检会查）；想新标签页打开的外链加 `External: true`。**开始菜单读的就是这一份**，改这里两处一起变 |

| `dark_theme.mode` | `auto` = 跟随系统深浅色 |
| `index_exclude_categories` | 「文字」列表（`/blog/`）里**不出现**的分类，默认只排掉 `作品`（2026-10-18 合并后不再排 `文章`，否则「文章」分类的篇目会从文字页消失） |
| `articles_category` | 旧「文章」分区的分类名，默认 `文章`。`/guides/` 变成跳转桩后它只剩一个用途：决定 `articles-redirect` 要生成几个 `/guides/page/N/` 跳转桩（N = 该分类篇数 ÷ `articles_per_page`）。`xp_num articles` 已于 11-07 随 guides 数据链删除 |
| `per_page`（在 `_config.yml`） | 列表每页篇数，现在是 **10**；`0` = 不分页 |

### 7.1 关机彩蛋的文字怎么改

开始菜单底部有个「**关机**」按钮（2026-10-14 加的小彩蛋）：点了会先弹一个模拟的系统错误窗口，
关掉它进入蓝屏，点任意位置（或按任意键）恢复原样 —— 纯前端演出，不会影响浏览器或系统。

**所有文字都在 `_config.yml` 的 `shutdown:` 段里改，不用碰代码**（改完菜单按 `2` 生效）：

| 配置项 | 显示在哪 | 不填时 |
|---|---|---|
| `button` | 开始菜单底部那个按钮上的字 | `关机` |
| `error_title` | 错误弹窗的**标题栏** | 站点名（`_config.yml` 的 `title`） |
| `error_lines` | 错误弹窗的**正文**（写几条就是几行） | 两行默认文案 |
| `error_ok` | 错误弹窗的**确定**按钮 | `确定` |
| `bs_head` | 蓝屏**顶部**那行大字（可用 `{site}` 代表站点名） | `{site} 遇到问题需要关闭` |
| `bs_lines` | 蓝屏的**正文段落**（写几条就是几段） | 一段默认文案 |
| `bs_progress_suffix` | 蓝屏里进度条**后面**的字（百分比会拼在前面，如 `47% 完成`） | `完成` |
| `bs_code` | 蓝屏的**停止代码**那一行 | `停止代码：SITE_EASTER_EGG_NOT_SUPPORTED` |
| `bs_foot` | 蓝屏**最下面**那行提示 | `点击任意位置（或按任意键）重启你的浏览器` |
| `sound` | **音效开关**：`true` 点「关机」有一声错误音「咚」、进蓝屏有一段下行关机音 | `true`（开） |

改法示例（只改冒号后面的内容，**保留缩进**）：

```yaml
shutdown:
  button: 关机
  error_title: 我的小站
  error_lines:
    - 关闭计算机时发生严重错误。
    - 系统即将停止响应，未保存的内容将会丢失。
  bs_head: '{site} 遇到问题需要关闭'
  bs_code: '停止代码：SITE_EASTER_EGG_NOT_SUPPORTED'
```

> **放心改**：每一项都有内置兜底，**整段删掉彩蛋也照常能跑**（只是文案回到默认）。
> `error_lines` / `bs_lines` 是列表，加一行就多一行文字，行首的 `- ` 不能丢。

**关于音效**：声音是浏览器**现场合成**的（Web Audio，和首页烟花同一套做法），
**不引入任何音频文件**，不占仓库体积。两层开关：

- `_config.yml` 里 `sound: false` → 全程安静；
- 任务栏右下角托盘的**静音按钮**优先级更高 —— 静音开着时 `sound: true` 也不出声。

**不想要这个彩蛋？** 把 `_config.yml` 里 `shutdown:` 整段删掉，按钮会显示默认的「关机」二字并**仍然可用**；
想彻底去掉按钮，需要改 `scripts/xp-taskbar.js`（进阶，改前先按 `4` 备份）。

**`_config.yml` 的红线（AI 也不要动）**：

| 项 | 为什么 |
|---|---|
| `deploy:` 整块（`repo` / `branch`） | 改错就发布不了 |
| `permalink: :title/` | 全站网址规则（不带日期）。改了**所有文章的旧链接失效**，2026-10 刚换过 |
| `marked.html: true` | 允许正文写 HTML（XP 版式靠它），改 `false` 毁掉全站版式 |
| `theme` / `url` | 主题名别改；`url` 写错则分享卡片与图片链接全错 |

⚠️ 刻意保持关闭、**不要随手打开**：`toc`、`image.lazyload_enable`、`image.photo_zoom`、
`cdn`、`search`、`comment.enable`（打开会引入重复锚点、重复窗口、失效样式，配置里每项都写了原因）。

## 8. 改完怎么生效 · 发布 · 备份 · 撤回

### 8.1 改完「生效」的规则

| 改了什么 | 要做什么 |
|---|---|
| 文章、图片、样式、模板 | **菜单按 `2` 重新生成**，然后浏览器刷新（`Ctrl + F5`） |
| `source\_data\` 里的文件 | **先关预览窗口 → 菜单按 `2`**（预览只在启动时读一次数据） |
| `scripts\*.js` | **先关预览 → 菜单按 `2`**（构建期脚本只在启动时加载一次） |

> **一句话：任何改动都要按 `2`。** 曾经以为菜单 `7` → `[1]` 起的预览带「热重载」、
> 改完文章刷新浏览器就行 —— 2026-10 实测**不成立**：改完 `source\_posts\*.md`
> 盯着服务器日志等 30 秒，日志一行都没新增，页面始终是旧内容。
> 本机的 `hexo server` 只服务**启动那一刻生成的那份快照**。
>
> 所以开预览的定位是「**先把站点挂起来，省掉反复关停预览**」，不是「免重新生成」。
> 写文章时仍然推荐开 `7` → `[1]`（浏览器一直挂着，看一眼结构方便），
> 但每改完一轮内容，回菜单按 `2` 再刷新。

**发布前自检（顺序别换）**：① 菜单 `2` 重新生成，无报错 → ② 菜单 `6` 自检，要「全部通过」
→ ③ 看首页 / 作品页 / 文字页 / 一篇文章，宽屏与窄屏各一次、深色模式一次 → ④ 满意再按 `3`。
构建前先停预览（`2` / `3` 会问你）：两边同时动 `public\` 偶尔会「构建成功但 public 没了」。

### 8.2 发布（菜单 `3`）与卡住

| 选项 | 什么时候用 |
|---|---|
| `[1]` 只重传 | 上次卡在上传（代理 / TLS 报错）且之后没改过内容 —— 几秒补传 |
| `[2]` 重建并上传 | 平时正常发布 |

三步：清理 → 生成 → 上传（推到 GitHub 的 `gh-pages` 分支，线上 **https://jawooth.github.io/**）。

**卡在 `Writing objects: 100%` 不动**：不是你操作错了 —— git 经本机代理（Clash Verge）走 HTTP/2
的老毛病，卡在「等服务器回执」。先等 1~2 分钟；不动就菜单 `3` → `[1] 只重传`（东西已提交好，
不会丢，**不必重新生成**）。**不要连点两次发布**；**代理必须开着**（直连连不通）。
发布成功 ≠ 线上立刻更新（Pages 还要构建 30~120 秒，之后 `Ctrl + F5`）。

**怎么确认传上去了**：按 `6` 自检；或让 AI 跑 `git -C D:\tools\hexo\.deploy_git log -1`
（`.deploy_git\` 是部署时克隆的 gh-pages 副本，**第一次部署会重新建**，出现刚刚时间的
`Site updated: …` 就是成功了）。

**另一条路：GitHub Actions 自动部署**（`.github\workflows\deploy.yml`）：push 到 `master` 就触发，
由 CI 完成「`npm ci` → 构建 → 自检 → 推 gh-pages」，不经本机代理，也就没有上面那个 TLS 卡住的坑。
两条路可以并存：本机菜单管「随手改随手发」，CI 管「提交记录即发布」。

> **CI 已于 2026-11-07 跑通**（master 首次推送后 48 秒完成，gh-pages 紧接着构建成功）。
> 之前一直是「配了但没生效」：仓库当时**没有 remote**，`deploy.yml` 从未被触发；
> 构建资源（`source/fonts/`、`source/images/`、`source/vendor/`）也还没入库。
> 现在这些都已在版本库里 —— **CI 从仓库 checkout 构建，本地文件没提交就等于线上没有**，
> 这是它和本机部署最大的区别。
>
> 查 CI 结果：仓库页 → Actions →「构建并部署到 GitHub Pages」。
> 它跑的是 `python3 tools/check/verify-site.py --no-audit`（故意跳过 npm audit，
> 因为 CI 到 registry.npmjs.org 偶发 ECONNRESET，不让它拦住部署）。

### 8.3 备份与撤回（后悔药）

| 我想… | 怎么做 |
|---|---|
| 动手前留个底 | 菜单按 `4`（文章、图片、数据 → `backup\日期时间\`） |
| **放弃刚才所有改动** | 菜单按 `5`（先列出被改 / 删的文件，输 `y` 确认才执行） |
| 看今天改了什么 | 让 AI 助手跑 `git status`，或看菜单 `5` 的提示 |
| 让别人（或 AI）接手改站 | 把本文第 12 节发给它 |

> `backup\` 不进仓库、不会被发布，可以放心堆。按 `5` 撤回的是**源文件**，撤完接着按 `2`
> 页面才会变；`backup\` 不受影响，所以「先备份，再撤回」最稳。

## 9. 出问题了怎么办

### 9.1 按现象查

| 现象 | 多半是这个原因 | 怎么办 |
|---|---|---|
| **发布了，线上却没变** | 见 [0.1 问题三](#01-三个最容易搞混的问题) | 先看发布窗口最后一行是不是 `✓ 完成` |
| 提示 4000 端口被占用 | HexoHub 的预览开着，会打断构建 | 按提示停掉它，再继续 |
| 报 `TLS connect error` / `unable to access` | 本机代理（Clash Verge）掉了。**内容没丢** | 重新按 `3`，选 **[1] 只重传** |
| 卡在 `Writing objects: 100%` 不动 | 代理 + HTTP/2 的老毛病 | 再按一次 `3` 选只重传；详见 [8.2](#82-发布菜单-3与卡住) |
| 改了 `_data` 里的文件，预览没变化 | 预览只在启动时读一次数据 | 关掉预览 → 菜单按 `2` |
| **文章里的图在 HexoHub 预览里不显示** | **HexoHub 的预览不读磁盘图片**，不是图没放对 | 菜单按 `7` → `[1]` → 浏览器刷新看 |
| HexoHub 里选「服务器预览」报 `Cannot GET /2026/…` | 它按 `/年/月/日/标题/` 拼地址，本站没日期 | 「iframe地址获取方式」改选**「根地址」** |
| 改了东西，网站没变 | 忘了重新生成 | 菜单按 `2` |
| 样式改了没反应 | 浏览器缓存 | `Ctrl + F5` 强制刷新 |
| 双击 `public\index.html`，页面是纯文字、图全没了 | 构建产物不能用 `file://` 打开 | 用菜单 `2` 打开预览 |
| 中文变成 `?` | 用 PowerShell 命令改过中文文件 | 菜单按 `5` 撤回，改用记事本改 |
| 页面里冒出一堆 `{% xp_xxx %}` 原文 | 模板标签没被渲染（多半是缩进 / 注释踩坑） | 按 `6` 自检，看是哪一页；再对照 [10.3](#103-页面模板与内容标签) |
| **正文整段变成灰底等宽字（像代码）** | **粘贴时把缩进带进来了：缩进 4 空格的行被当成代码块** | 把每行前面的空格删掉**顶格写**；只有代码才缩进，且要用 ``` 上下包起来 |
| 敲 `py -3 tools\xxx.py` 报「找不到文件」 | 不在博客目录里，或脚本挪了子目录（图片类在 `tools\images\`） | 双击 `1 开始使用.cmd` 最省事 |
| 作品图导出来横竖颠倒 / 透明变黑 | 没走脚本（或用了旧版脚本） | 按 3.2 重新导入；作品图一律走脚本 |
| 改了关机彩蛋的文案，页面上没变 | 配置改完要重新生成 | 菜单按 `2`（见 [7.1](#71-关机彩蛋的文字怎么改)） |
| 网站整个打不开了 | 先别慌，八成是改坏了 | 按 `4` 留底 → 按 `5` 撤回 → 按 `2` 看效果 |

### 9.2 万能兜底

**任何一步「好像坏了」，先按 `5` 撤回**，网站就回到上次能用的样子，然后慢慢再来。
撤回前想保险，先按 `4` 备份。完全不知道从哪下手？把本文发给 AI 助手，说「我要改 XX」。

## 10. 外观进阶

### 10.1 颜色变量（`source\css\xp-custom.css`）

| 变量 | 管什么 | 浅色默认 |
|---|---|---|
| `--xp-blue-border` | **窗体 / 按钮 / 气泡边框、标题栏主色** | `#0054e3` |
| `--xp-blue` / `-light` / `-dark` | 标题栏渐变三层 | `#0058ee` / `#3590f3` / `#003399` |
| `--surface` / `-2` / `-3` | 窗口卡片底 / 按钮芯片底 / 空状态底 | `#ffffff` / `#f7f6f0` / `#ece9d8` |
| `--text` / `--text-heading` / `--text-muted` | 正文 / 标题 / 次要文字 | `#000000` / `#003399` / `#6b6b6b` |
| `--border` / `--border-strong` | 分隔线 / 加重的边 | `#d0cfbf` / `#a8a79a` |
| `--link` / `--xp-hover` | 链接 / 悬停底色 | `#0000ee` / `#316ac5` |

**换个主题色 = 改 `--xp-blue-border` 一处**，窗体、按钮、气泡边框一起变。
改 CSS 只需刷新页面（顽固时 `Ctrl + F5`），不用重新生成。

> **深色模式规则**：变量若在 `:root` 和 `html.dark` **两块都出现**（背景、文字、边框这类）
> → **两处都改**，否则深色下看不清（最常见的错）；**只在 `:root` 出现**的（`--xp-blue*` 一族、
> 任务栏渐变、装饰图路径等）→ **只改一处**，深色自动跟着变。`--xp-blue-border` 就属于只改一处的那种。

### 10.2 字体

全站两套像素字体（主题自带的那套 iconfont 已于 2026-11-03 随瘦身删除 —— 那些元素没有文字，视觉早由 `xp-icons.css` 接管）：

| 项目 | 情况 |
|---|---|
| 正文字体 | 缝合像素 12px（Fusion Pixel Font，作者 TakWolf）· `source\fonts\fusion-pixel-12px-proportional-zh_hans.woff2`（**约 177 KB 子集**：GB2312 + 仓库实际用字） |
| 强调字体 | 缝合**粗**像素 12px（真粗体）· `fusion-bold-pixel-12px-proportional-zh_hans-subset.woff2`（约 180 KB 裁剪版） |
| 许可证 | SIL OFL 1.1，原件随字体放在 `source\fonts\`（OFL 要求随附，**别删**） |
| 字号 | **五层**（13.3.3）：界面 `--fs-ui` 16、正文 `--fs-text` 16、标题 32/24/20/18、屏内 11–15、注脚 `--fs-note` 14 |
| 行距 | **三层**（13.3.4）：长文 1.75、短段落（裸 `p` 的默认值）1.6、标题 1.3–1.45。界面元素继承 `modern-normalize` 的 **1.15** —— 覆盖 303 个元素，是 XP 控件的基础格线，不是「散落的旧值」 |

**关于「锐利」**：点阵字体设计尺寸 12px，只有 12 的整数倍缩放才完全锐利。
站主选择**可读性优先**（正文 16px = 放大 1.33 倍），代价是笔画有极轻微粗细不匀。
想恢复完全锐利：把 `:root` 的 `--fs-ui` / `--fs-text` 改成 `12px`（两处一起改，改完必须重跑
`audit-layout.js` 与 `audit-type.js`）。**不要**在正文里用 13~15px 这种中间值 —— 那几档只属于
播放器屏内（13.3.3）。

**XP.css 自带的字体不会被下载**：库里 `ms_sans_serif` / `PerfectDOSVGA437Win` 两套 woff2（共约 30 KB）
只被 XP.css 自己的 `button` / `input` / `pre` 等选择器引用，而那些选择器全被 `xp-custom.css`
第 16 节覆盖掉了，浏览器不会去请求 —— 访客只会拿到上面这两套缝合像素字体。

| 想做的事 | 怎么做 |
|---|---|
| 换整套字体 | ① 新 woff2 放 `source\fonts\`；② 改 `xp-custom.css` 第 0 节 `@font-face` 的 `src` 与名字；③ 改 `:root` 的 `--font-ui`（和 `--font-display`） |
| 只改正文字号 | 改 `:root` 的 `--fs-text`（67 处引用随之变）。别去单处改 `font-size` |
| 给 16px 标题加粗？ | **别加**。点阵合成粗体会把笔画糊成一团；要突出就换字色（蓝色）。真粗体只给 24px 的用户名 / 作者名用 |
| 斜体同理 | 别用 `font-style: italic`，会合成假斜体把点阵糊掉 |
| 重新裁剪字体 | `py -3 tools\fonts\make-pixel-fonts.py <正文 woff2> <粗体 woff2>`（只有粗体那套会被裁剪；改了网名后重跑一次） |

> **缺字监控**：字体是子集化的，新文章出现未收录的汉字会**静默回退系统字体**。
> `tools\check\verify-site.py` 每次自检都会算「文章用字 ∩ 字体覆盖」，缺字会提醒你重跑裁剪脚本。

### 10.4 样式是怎么排的：三层 + `@layer`

全站样式由**三个**文件按固定顺序叠加，注入点只有一个：`scripts\inject-xp-css.js`。

| 顺序 | 文件 | 作用 | 能不能改 |
|---|---|---|---|
| 1 | `style\main.css` | 主题自带样式（由 `themes\minimalism\source\style\*.styl` 编译出来）。**2026-11-03 瘦身后只剩 52 行 / 1 344 B 的浏览器重置**（`*{margin:0;padding:0}`、`html{line-height:1.15}`、表单控件 reset），版式与配色全在 `xp-custom.css` | 要改就改 `.styl`；但**别再往这里加东西** —— 它存在的唯一理由是「必须未分层才压得住 XP.css」 |
| 2 | `vendor\xp-css\XP.css` | XP.css 官方库 v0.3.0，**自托管**（MIT） | 只按 `source\vendor\xp-css\README.md` 的流程整体升级 |
| 3 | `css\xp-custom.css` | 本站设计系统（**唯一真源**，改样式基本都改这里） | 随便改 |

**关键**：第 2 个文件整份被包在 CSS 级联层 `@layer xp-css{ … }` 里。分层样式**一律**输给
未分层的样式 —— 跟谁的选择器更具体无关。所以第 1、3 层（都未分层）永远赢，
XP.css 只在「本站没写过的地方」生效。

为什么非包不可：XP.css 是**元素选择器**为主的库，原样引进来会让全站字号从 16px 掉到 12px、
每个图标按钮从 28px 宽变 75px 宽、站内链接全变蓝、代码块换成 DOS 字体……（完整清单和逐条压回
规则在 `xp-custom.css` 第 16 节「XP.css 兼容层」，每条都写了「不改会怎样」）。

**为什么自托管而不是 CDN**：① 版本钉死（0.3.0），库哪天偷偷更新不会影响本站；
② 少一次第三方请求，而且 XP.css 自带的字体不会被下载（省约 30 KB）；
③ 只有自托管这份带 `@layer` 包裹，CDN 上的原文没有 —— 直接引会把上面的问题全引回来。

库文件的来源、sha256 校验、4 步升级法：`source\vendor\xp-css\README.md`。
`tools\check\verify-site.py` 每次构建都会盯着：副本在不在、`@layer` 包裹有没有掉、`LICENSE` 在不在、
是不是每个页面都引到了、以及三个样式表的顺序对不对。

### 10.5 坑清单（踩过的，改之前看一遍）

1. **改 `_data\*.yml` 不生效**：预览启动时读一次内存 → **关预览 → 菜单 `2`**（增量生成也感知不到
   `_data` 与 `scripts\*.js`，所以 `2` 带清理）。
2. **改 `scripts\*.js` 必须重启预览**：构建期脚本只在启动时加载一次（模板 / 样式会热加载）。
   **`hexo server` 在本机没有热重载**（2026-10 实测：改完文章 title 盯日志 30 秒，新增 0 行，
   页面 `<title>` 始终是旧值 —— 不是配置里关了 watch，而是它依赖的文件监听在本机不生效）。
   它**只服务启动那一刻生成的那份快照**，所以「开预览」的价值是「把站点挂起来、省掉反复关停」，
   不是「省掉重新生成」——改完内容仍然必须按菜单 `[2]`。
   规律：凡是「靠文件监听自动更新」的能力，不要凭直觉写进用户说明，实测一次日志增量再写。
3. **同一个 `id` 一页只能出现一次**（`getElementById` 只命中靠前那个）；同名 class「后声明者胜」。自检会查。
4. **深色模式成对写**（见 10.1）。
5. **含中文的文件别用 PowerShell 的 `-replace` / `Set-Content` 改**：中文变 `?`，YAML / CSS 直接损坏。
6. **`public\` 是构建产物**：不要手改、不要提交。`source\` 里以 `_` 开头的文件会被忽略（测试稿用 `draft-`）。
7. **别删「看似没用」的东西**：`decor\left.png` / `right.png` 是可选装饰图（自检白名单）；
   主题自带搜索是**故意关的**（站点用自己的搜索框 + 构建生成的 `/search.json`）。
8. **主题是自持的**：不要 `npm i hexo-theme-minimalism`，改 `themes\minimalism\` 即可。
   **依赖锁死，不要 `npm update`**。
9. **图片按用途分档 + 头像名固定**：默认卡片缩略图 `*-thumb.*`（4:3；瀑布流下可换成任意比例的图，见 3.4）、正文中图 `*-800.*`、
   放大图 `*-1600.*`，每档都有 WebP 与 JPEG 两份；头像必须叫 `site-avatar.png`。
10. **`.ps1` 必须存成「UTF-8 带 BOM」**（PowerShell 5.1 把无 BOM 的 UTF-8 当 ANSI 读）；
    **中文文件名的 `.cmd` 正文必须纯 ASCII**（中文都在 `tools\hexo-ui.ps1`）。
    实测教训：`tools\hexo-ui.ps1` 被工具默认存成**无 BOM** 后，PS 7 下语法检查照样通过，
    但双击 `1 开始使用.cmd` 直接崩 —— PS 5.1 按 GBK 解码，报出几十条
    `缺少右"}"` / `意外的标记"绔彛"` 这类**看着像语法错误、实为编码错误**的乱码提示。
    见到乱码提示先查编码；改完用 PS 5.1 复核（10.5 第 10 条）。
11. **窄屏下 `flex-basis` 会变成「高度」**：容器改纵向时要同时复位子项。
12. **别在 `body` 上加全站 `line-height`**：`modern-normalize` 给 `html` 的 1.15 会继承到每页 500+ 个元素，
    但那些几乎都是**单行**界面文字 —— 行高只决定盒高、不改字形。统一抬到 1.6 会让 XP 桌面所有紧凑
    控件整体长高约 27%（实测 `.xp-window-body` 262.9→334.9px），是视觉回归不是优化。
    要补行高就补在 `xp-custom.css` 的 **2-b 节**，并且只针对**会折行**的元素。
13. **双栏转单栏时必须给主列补 `max-width`**：侧栏从右侧掉到下方后，主列失去了
    「总宽 − 侧栏」这个天然约束，会一路撑满容器。实测文章页每行从 33 字跳到 **52~58 字**，
    超出「中文舒适区 30–45 字/行」（`xp-custom.css:1466` 写着这条标准）。
    正确写法见 `xp-custom.css` 的 `@media (max-width: 900px)`：`max-width: 720px`（45 × 16px）。
14. **改样式前扫一眼第 13.7 节的「反规则清单」**：那里列的是
    「不要做什么」，正是容易被无意写回去的东西（圆角卡片、灰底、Inter、细线图标、柔和阴影）。
    标 ⭐ 的四条已由 `tools\check\verify-site.py` 的「审美门禁」自动检查。

  会在它们再出现时报错。要重新启用某功能，再从 npm 包取回。
- **外链**：所有 `target="_blank"` 都要带 `rel="noopener noreferrer"`，否则新窗口能通过
  `window.opener` 反向控制本站（页脚、导航已补齐）。
- **大文件 / 客户端**：客户端一律装仓库外面（HexoHub 在 `D:\tools\HexoHub`，约 20 MB）。
- **密钥**：评论、统计、algolia、CDN 全部留空 / 关闭；`.gitignore` 已含 `.env*`、`*.pem`、
  `*.key` 等。提交前可自查：`git -C D:\tools\hexo diff --cached | Select-String -Pattern 'secret|token|password|PRIVATE KEY'`。
- **公开可下载**：`/search.json`（全站标题与摘要索引）任何人都能下载，别写不想公开的内容。
  ~~`/works-bodies.json`~~ 已随瀑布流改版删除，不必再考虑。
- **页面会请求的第三方**：只有网易云（封面 `p1.music.126.net`、音频 `music.163.com`）；
  其余全自托管（字体、播放器、图标）。播放器封面走域名白名单（`scripts/xp-player.js` 的 `safePic()`）。

  `dependabot.yml` 每周一给 npm / Actions 依赖开升级 PR（不自动合）。升级 PR 要一条条看：
  版本号一律 `--save-exact` 钉死，出问题 `git checkout package.json package-lock.json` 就回滚
  （2026-11-06 站主取消了「一次只升一个包」的硬性节奏，但保留可溯源、可回滚的要求）。

### 13.3 版式：断点、圆角

#### 13.3.1 断点：主档 640 / 900 / 1200，另加六个补丁档

`xp-custom.css` **第 13 节**的标题写着「统一 640 / 900 / 1200」。新写响应式规则时**只用这三个**。

| `641 ~ 900` | 单栏，侧栏移到正文下方 | 主档 |
| `≤ 640` | 手机，间距再收 | 主档 |
| `641` / `901` | 与主档差 1px | 「≤640 与 ≥641」这类成对写法，避免 640/641 那一像素同时命中 |

XP 的圆角不是「设计感」，而是**材质语义**：越像实体窗体越直，越是小控件才略有圆。
下表就是 `verify-site.py` 审美门禁放行的**全部**值（`ALLOWED_RADIUS`），写表外的数字自检会报。

| 圆角 | 用在哪 | 例子 |

| `0` | 窗体、卡片、面板、图片边框 | `.xp-window`、`.work-card`、便当格卡 |
| `2px` | 窗口内的小块、标签、输入框 | `.xp-badge`、`input`、行内 `code` |
| `3px` | 按钮、标题栏按钮（**默认值**） | `.xp-button`、`.xp-window-btn` |
| `4px` | 小控件、圆角头像 | 头像一族 |

| `8px` | 邮箱弹窗的小标签 | `.profile-email-pop .email-label` |
| `9px` / `11px` | 作品标签、作品页筛选胶囊（**在案的历史遗留**） | `.work-tag`、`.filter-pill` |
| `12px` | 文章信息条的小胶囊徽标 | `.meta-chip` |

门禁的判法是「同一规则块里同时出现 8~16px 圆角和 `box-shadow`」才算命中，因为那正是现代组件库

其余胶囊都是 `3px 10px` —— 记在 14.1，别在别处顺手改。

**怎么验**（行高改动会改高度，截图看不出一两像素）：把 `HEAD` 与工作区的产物各构建一份、起两个静态端口，
用 CDP 并排读每个目标元素的 `computed lineHeight`、`height`、`height/lineHeight` 行数 —— **行数不变才算安全**。
便签这类有固定纸高的还要单独看 `scrollHeight - clientHeight`。

#### 13.3a 往里注入 JS 时，注意四件事

本站大量代码是**构建期把 JS 当字符串拼进页面**的（`xp-enhance.js` / `xp-taskbar.js` /
`xp-player.js` / `xp-content.js`）。这类代码有个共同的坑：**外层 `node --check` 查不到内部错误**。
踩过的三次，每次都是「页面静默失效、控制台一个 SyntaxError」：

1. **模板字符串里的花括号不配对 → 静默失效**。替换 `bind()` 时多留了一个 `}`，
   注入到页面后是 `SyntaxError: Unexpected token 'function'`，点赞点了没反应，
   而 `node --check scripts/xp-enhance.js` **照样通过**（因为它检查的是外层文件）。
   → **对策**：拼完后把注入的 JS 单独抽出来再查一遍语法。本项目用过两种方式，都有效：
   ① 在脚本里 `new Function(jsString)`（只编译不执行）；
   ② 构建后从 `public/*.html` 里用正则抠出那段，写成临时 `.js` 再 `node --check`。
2. **包 IIFE 才有命名空间边界**。同一段注入代码里的 `startGlitch` / `stopGlitch` 曾分别定义在
   `shutdownSequence` 内部与 `showBlueScreen` 里 —— 两者是**兄弟**不是嵌套，
   蓝屏时点击恢复直接 `ReferenceError: stopGlitch is not defined`。
   → **对策**：一对儿函数要么同层，要么显式传参，不要靠"看起来在一个块里"。
3. **构建期读不到运行时的东西**。「访客屏幕多宽」「是不是旋转屏」**只能放运行时**
   （构建期不存在这些值）——构建期只适合「开关」这类静态判断。
   → 反例（已修）：粒子背景原本按「宽 > 768 才加载」的意图无条件下发了 `<script src>`，
   结果 390px 手机上照跑一个 canvas + rAF（2026-10 已修，该库后于 2026-10 整体移除）。
4. **改完 `scripts\*.js` 必须重启预览**。构建期脚本只在启动时加载一次；
   不重启会拿到**内存里的旧代码**，然后误判"修复无效"。本项目在这上面浪费过一整轮排查。

#### 13.3b 必须从「数据源」而不是「渲染结果」读的东西

- **加密文章的字数统计**：`wordChip(ctx, post)` 原本调 `wordcount(post.content)`，
  但 `hexo-blog-encrypt` 渲染后把 `post.content` 换成了**密码框那几十个字符的 HTML**，
  于是加密文章显示「8 字」（实际 446 字）。
  → **对策**：`post.password && post.source` 时改从源文件读
  （`fs.readFileSync(path.join(hexo.source_dir, post.source))`，再用
  `/^---\r?\n[\s\S]*?\r?\n---\r?\n?/` 去掉 front matter）。
  **规律**：任何"插件加工过 `post.*` 字段"的地方，统计与摘要都要回到源文件。

### 13.4 拿几何尺寸一律用 `getBoundingClientRect()`

播放器「跑到画面外」排查了两轮都猜错，真因是 `clampPos` 用了
`box.offsetWidth * scaleOf(box)`。反推出一个 217px（既不是 200 也不是 250）才找到问题。

- `offsetWidth` **不含** `transform: scale()` 的效果，也不含小数；缩放过的东西必须用
  `getBoundingClientRect()`。
- 视口尺寸优先 `visualViewport`（移动端软键盘弹起时 `innerWidth` 不变，`visualViewport` 才准）：
  变焦、`orientationchange`、恢复位置之后都要**重新夹取一次**（本项目在 120/260/350/800/1000ms
  多个时点补夹，因为布局是异步稳定的）。
- 顺带：`transform-origin` 用 `top left`。用 `bottom right` 时 1.25× 会把左边推出屏幕
  （视觉 left = `left − 50`），0.8× 时右下角又够不到。

### 13.7 反规则清单：不要做什么

第 1–6 节讲「该怎么做」。这一节反过来列**不要做什么** —— 因为「该怎么做」需要判断力，
而「不要做什么」可以直接照做，也正好是 AI 助手最容易无意中写回去的东西
（现代组件库的默认长相：圆角卡片 + 灰底 + Inter + 细线图标 + 柔和阴影）。

**这份清单的 ⭐ 条目已经由 `tools\check\verify-site.py` 第 10 节「审美门禁」自动检查**，
构建后会提醒。其余条目靠自觉。

#### 13.7.1 颜色

| ❌ 不要 | 为什么 |
|---|---|
| 在 `xp-custom.css` 里写新的十六进制颜色 ⭐ | 只用第 1 节的 token。换主题色应该只改 `--xp-blue-border` 一处 |
| 用 #F4F4F5 这类灰做卡片底（zinc / slate / stone / gray 面） | 本站底色是 `--surface` #ffffff 与 `--surface-2` #f7f6f0，灰卡片会让 XP 窗口变「现代后台」 |
| 紫蓝「AI 渐变」（#8B5CF6 → #3B82F6）⭐ | 全站唯一允许的渐变是浅蓝任务栏渐变与像素壁纸 |
| 用色调给文字染色 | 只用 `--text` / `--text-heading` / `--text-muted`，次要文字才用 `--text-muted` |
| 同一屏里混两套色调 | 会显得像两个站点拼起来 |

#### 13.7.2 字体与字号

| ❌ 不要 | 为什么 |
|---|---|
| 引入 Inter / Roboto / Helvetica / Arial ⭐ | 全站自托管像素字体，引入现代无衬线会立刻「不像本站」 |
| 把 `system-ui` 当字体名 ⭐ | 同上。它只能出现在 fallback 栈的**末尾** |
| 给 16px 标题加粗、用 `font-style: italic` | 点阵字体在非整数倍合成粗体会把笔画糊成一团（10.2） |
| 在正文里引入 13 / 15px 中间字号 | 屏外只有 16 和注脚 14（`--fs-note`）两档，门禁会拦；11–15px 只属于播放器屏内，见 13.3.3 |
| 把全站行距「统一」成 1.6 ⭐ | 行距分三层（13.3.4）：长文 1.75、短段落 1.6、标题 1.3–1.45。界面元素那个 **1.15** 是 XP 控件的基础格线，改了会把 303 个元素撑高 27% |
| 给 `padding` / `gap` 造一套 `--sp-*` token | 间距是组件局部决定，不成比例的四边组合很多；理由写在 13.3.4，别再试 |

#### 13.7.3 形状与阴影

| ❌ 不要 | 为什么 |
|---|---|
| 给浮动卡片加 8–16px 圆角 ⭐ | 那套圆角只属于「坐在细条纹**上**」的凹槽与分组框；XP 味儿来自直角与 2px 描边（13.3.2） |
| 给卡片加 `0 4px 12px rgba(0,0,0,.1)` 这类柔和投影 ⭐ | 阴影只给窗口 / 菜单 / 提示框 / 开始菜单这类**浮层** |
| 用细线图标（Lucide / Heroicons / Feather 风格） | 本站图标全是手绘内联 SVG 或像素图形，细线线性图标风格不符 |
| 在 XP 组件上套大圆角卡片风格 | 同上，与 13.3 的直角基调冲突 |

#### 13.7.4 结构与版式

| ❌ 不要 | 为什么 |
|---|---|
| 建「现代落地页」式的页面（hero 大标题区、居中最大宽单列、三列特性网格、链接列页脚） | 本站的布局模型是 **desktop 不是 page**：内容住在窗口里，导航住在任务栏与开始菜单里 |
| 用 `!important` 堆叠来修层叠问题 | 本站现在只有 16 处 / 4 064 行；`@layer` 已经让覆盖变得可控（见 13.2），先查是不是用错了层 |
| 在 `body` 上加全站 `line-height` | 会继承到每页 500+ 元素；实测 `.xp-window-body` 262.9 → 334.9px，紧凑控件会长高约 27% |
| 把组件样式从 `xp-custom.css` 抄到别的 `.css` ⭐ | 唯一真源。v3.0 时代抄成 6 份、同一组件三套值、深色模式半失效，别再演一遍 |
| 加「友好的空状态插画」「每个字段下的 helper text」 | 这两样是典型现代 Web 味，与 XP 风格冲突 |

#### 13.7.5 交互

| ❌ 不要 | 为什么 |
|---|---|
| 做 pulse 呼吸动画、窗口缩放动画、弹跳 | 已全站尊重 `prefers-reduced-motion`（8 处覆盖点），别新增动效时绕开它 |
| 给 16px 文字用 mid-gray（`--text-muted`）当正文 | `--text-muted` 只给 16px 的次要说明；正文一律 `--text` |

### 13.8 一句话总结

**XP 的壳，像素的字，蓝得克制，深色成对，改样式只碰 `xp-custom.css`。**
**加组件先查 13.3.1 断点与 13.3.2 圆角表；注入 JS 记得单独查语法（13.3a）；量尺寸用 rect（13.4）；动样式前扫一眼 13.7；改 `hexo-ui.ps1` 别弄丢 BOM（10.5 第 10 条）。**

### 14.3 变更记录（倒序）

> 只记结论与坑。详细过程在 git log 和代码注释里，这里记的是**下一次动同一块地方时该知道的事**。

#### 2026-11-07 · 行高收敛：长文 1.75 / 短段落 1.6（13.3.4）

- **先分清层再动手**：`line-height` 48 处 / 20 种，但只有三段是「行距」决策 —— 长文 1.75、短段落 1.6、标题 1.3–1.45。看着最碍眼的那个 **`1.15` 基准值反而是不能动的**：渲染态统计里它覆盖 **303 个元素**（窗口标题、任务栏、徽章、播放器 chrome），是 XP 材质本身的格线，改成 1.6 会把全站控件撑高 27%。
- **收敛 8 处，全部行数不变**：`.about-home-body p` 1.7→1.75、`.xp-bs-inner` 1.8→1.75、`.xp-post-card-excerpt` 1.7→1.6、`.work-card-desc` 1.55→1.6、`.bubble-quote`（含 ≤900 那条）1.55→1.6、`.hbe-hint` 1.5→1.6，加上下面两条。
- **两条查实「从未生效」后处理**：① `.post-content ul, ol` 的 `1.725` —— `li` 被上一行 `.post-content p, li { 1.75 }` 直接命中，从不继承 ul 的值，所以改它对页面零影响（两版产物对比 d=0，4 个 li 的 `line-height` 改前就是 28px）；② `.profile-text p` 的第一条（`1.55` + `margin:3px`）被后面 17px/1.5 那条整条取代，删掉。**同选择器打架这是本周第三次**（前两次是 `.bubble-from` 的 clamp、`.profile-text h2` 的 26px）—— 门禁扫不出来，只能建表时逐条对。
- **便签纸是唯一有硬约束的**：1.55→1.6 让溢出余量从 19px 缩到 13px，1440/1400/1240/1000/900 五档复测 `.bubble-content` 均无 `scrollHeight > clientHeight`。那条注释里早就写着「想再调大先跑一遍长句」，照做即可。
- **验证方式**：`HEAD` 与工作区各构建一份产物、起两个静态端口，CDP 并排读每个元素的 `lineHeight`/`height`/行数（`height/lineHeight` 取整）。比截图可靠 —— 一两像素的差在图上根本看不出来。
- **间距决定不做 token**（三条理由在 13.3.4）：奇数值也不是随手写的 —— 3px 是胶囊族的垂直内边距（6 个 `3px 10px`）、5px 是窄条行、7px 是 ≤640 触控补丁。唯一同族不同值 `.filter-pill: 3px 9px` 记进 14.1。
