写东西最烦的不是写，是每次都忘：开头那几行有哪几个字段、图片放哪个目录、标签写几个才不乱。这篇是自己的清单，开新稿之前扫一眼，比翻文档快。它本身是模板，不是文章 —— 真正的文章不长这样。

## 一、开头那几行

文章以两行 `---` 包住的一段开头，叫 front matter。它是 **YAML，不是正文**：冒号后面空一格，值里有冒号要加引号，缩进别用 Tab。写错了构建会直接失败，这反而是好事，一眼看得见。

最省事的三行：

```yaml
---
title: 标题写在冒号后面
date: 2026-11-08 20:00:00
categories: [随笔]
---
```

日期决定排序和归档年份，分类决定它出现在哪一栏。**标签可以完全不写**，写了才进标签云。

## 二、字段速查

| 字段 | 写什么 | 不写会怎样 |
|---|---|---|
| `title` | 文章标题 | 拿文件名顶替 |
| `date` | `2026-11-08 20:00:00` | 取文件创建时间，排序跟着乱 |
| `categories` | `[随笔]` 或 `[作品, 插画]` | 不进任何分类页 |
| `tags` | `[阅读, 笔记]`，宁少勿多 | 标签云里没有这个词 |
| `permalink` | `writing-reference` | 网址就是文件名 |
| `sticky` | 数字，越大越靠前 | 不置顶 |
| `desc` | 一句话简介 | 取正文第一段，超长截断 |
| `password` | 密码字符串，有前导 0 要加引号 | 不加密 |

三条经验：

1. 分类可以分层（`[作品, 插画]`），标签是平的 —— 分类最多两层，标签最多两个。
2. 中文标题配英文 `permalink` 最省事。不写的话网址就是文件名，复制出去是一串 `%E5%86%99...`。
3. **改 `permalink` 等于换网址，旧链接立刻 404**。已经发出去的文章别动这一行。

作品还有一套自己的字段（`origin`、`img`、`thumbnail`、`status`），那是给作品页用的，普通文章不用管。

## 三、正文能用的东西

标题从 `##` 起 —— `#` 留给文章标题，正文里再写 `#` 会和它打架。

- 列表就用减号，一行一条；
- 强调用 `**粗体**` 和 `*斜体*`，一段里别超过两处，否则等于没强调；
- 引用块放别人的话：

> 引用长这样。左边一条竖线，底色比正文浅一格。

代码块要标语言，标了才有配色：

```js
const answer = 42;
```

表格上面已经用过一次。列别超过五列，窄屏上要横向滚动才能看全。

图片写成 `![说明](/images/xxx.jpg)` —— **说明一定要写**，它同时是给看不见图的人读的。正文插图不会自动变成作品卡片封面，封面得在 front matter 里单独指定。

## 四、排版上自己定的几条

- 一段不超过四行。手机上一屏读完一段，眼睛才不累。
- 中文用中文标点，句号是「。」不是「.」。数字和英文两侧留一个空格，排出来不那么挤。
- 链接文字要能独立看懂，别写「点这里」。
- 小标题写陈述句，别用「关于……」这种空转的说法。
- 长文分节用 `##`，别拿加粗假装标题 —— 目录和锚点只认真标题。

## 五、写完以后

本地预览和构建两条命令：

```bash
npm run server   # 本地预览，改完刷新就能看
npm run build    # 生成静态文件
```

预览时重点看三件事：手机上正文有没有横向滚动、图片有没有被拉变形、暗色模式下字还看不看得清。
